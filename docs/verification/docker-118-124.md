Validated on 2026-09-14 JST in an isolated worktree combining PR #126 (`e1d622f`) and
PR #127 (`072d8c8`), plus the exit-reason fix described below. Host: macOS arm64,
Node 23.5.0, Docker Server 29.5.2. Containers: Node 24.20.0, Python 3.11.16.
Runs used a reused state dump containing all seven venues, not a fresh deployment.
All strategies were frozen (`ERIS_AGENT_FROZEN=1`); external LLM inference was not exercised.

## Docker recovery and image freshness

Docker initially had no reachable daemon. Its backend log recorded `no space left on device`
while writing `Data/log/vm/init.log`, followed by engine shutdown. A normal restart failed
because the old processes did not stop. `docker desktop stop --force --timeout 45` followed
by `docker desktop start --timeout 45` restored the daemon. Existing images and volumes
were retained; no factory reset or prune was performed.

Builds used the separate base tag `eris-agent-base:issues-118-124`. Existing team image tags
were backed up before replacement. `agent:build -- team` successfully built my-arb, noop,
my-arb-py and multi-arb. Generating SDK constants from the replay manifest and rebuilding
changed the base digest from `e8947b4d3715…` to `4b15eb4cce54…`. SHA-256 hashes of
`sdk/src/constants.local.ts`, `sdk/src/config.ts` and `example/agents/runtime/botMain.ts`
inside the rebuilt image matched the host source. A container also reached the dedicated
Anvil through `http://host.docker.internal:18651`.

## Regression found through Docker

A test-only image started the normal frozen runtime, then deliberately called `process.exit(137)`
after 15 seconds for my-arb only. No memory pressure was injected. The initial run,
`2026-09-13T17-04-56-275Z`, correctly returned FAIL / exit 1, but only the console and events
contained code 137: `summary.json` discarded it. As a result, self-test could not display the
termination code or possible-OOM hint.

The fix preserves code/signal in the exit reason emitted by `RealtimeAgentProcess`, which
the coordinator persists in `processExitedEarly`. The console uses that same reason, avoiding
duplicate details. The hint explicitly says that exit status alone does not prove OOM.
Regression tests now spawn real child processes exiting with 0, 1, 137, SIGKILL and a missing
executable, and pass their actual exit reasons to self-test instead of inventing reason strings.

The first post-fix attempt (`2026-09-13T17-11-19-343Z`) timed out during contract setup,
before containers started, on the repeatedly reused Anvil. The returned transaction hash had
neither a transaction nor a receipt when queried; the precise cause was not established.
The retry restarted only the dedicated Anvil from the same dump and set a new snapshot path
in YAML (`run.localSnapshotFile`). In YAML mode the non-secret shell variable
`ERIS_LOCAL_SNAPSHOT_FILE` is not imported, so an environment-only value does not isolate it.

The fresh-node retry, `2026-09-13T17-16-34-485Z`, completed all 24 blocks. It returned
FAIL / exit 1 as intended, and both the summary and verdict contained
`exited before the run ended (code 137)` with the possible-OOM caveat and fixture stderr.
Assertions checked the actual returned report, block count, termination details and exit status;
an unrelated setup failure cannot satisfy this negative test.

After the fix, typecheck, the real-child self-test/environment tests (15/15), and the full
suite passed: 838 tests, 834 passed, four existing local-deployment skips, zero failures.

This validation covers the exercised Docker paths and limits, not every regime, actual OOM,
fork mode, external inference, or the independent clean-clone walk requested after merge in #118.
