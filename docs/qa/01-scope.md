# 弱点を突く行為の範囲

競技規約 §3.1 と参加規約 第14条第2項に基づく「弱点を突く行為が認められる対象の一覧」について、判断の基準と、有効な攻撃・無効な攻撃の例をまとめました。正本は [ascon.dev/scope](https://ascon.dev/scope) です。ここと食い違ったら一覧が優先します。

ここでいう「有効」は、一覧の対象内であり、かつ競技規約 §8 と参加規約 第15条の禁止行為にも当たらない行為です。「無効」は、一覧の対象外か、禁止行為に当たる行為です。

対象に含まれるかどうか迷う場合は、実行する前に Discord で運営に DM で相談してください（一覧 §6）。

## Q. どこまで攻撃してよいのか、判断の基準は何か

一覧は次の 6 本の線で引かれています。上から順に当てはめ、どれか 1 本でも対象外に当たれば対象外です。

| 基準 | 対象内 | 対象外 |
|---|---|---|
| 1. 何を狙うか（一覧 §2） | 主催者が配置した 7 プロトコルを構成する全コントラクトとトークン（入口から辿れるものを含む）、他の参加単位のエージェントとその配置コントラクト、レジーム 7・11 で途中に出現するプールとトークン、環境の建玉・注文の相手方になること | 主催者の役割に限られた関数、オラクルへの書き込み、MarketRegistry と SimpleLending、Aave の試験用 Faucet、環境ウォレットの鍵、主催者の設備、競技環境の外 |
| 2. 他のエージェントは効果で判定（一覧 §2.2・§3） | 効果が「不利な取引を判断させる」「競技環境内の資産を失わせる」にとどまる行為 | 効果が「コードの実行・停止・認証情報の取得・外部への通信」に及ぶ行為。チェーン上の文字列で誘導する場合も、経路を問わず対象外 |
| 3. 対価を払うか（一覧 §3） | 取引の順序、薄い流動性、相手の判断の弱点など、コストかリスクを負って得る優位 | 無から資産を作れる、またはコストもリスクも負わずに誰の資産でも奪える欠陥。ガス代は対価に数えない。他者の資産を凍結するだけの欠陥も同じ。主催者が自作したコントラクトの欠陥は、この基準だけで判定 |
| 4. 上流に共通する欠陥か（一覧 §3） | 清算、オラクルの遅延、順序の予測など、プロトコルの仕様どおりの動作を前提とする経済的な戦略 | Uniswap・Balancer・Curve・Aave・GMX・Liquity の本物のコードに共通する脆弱性。参加者が複製して配置した場合も同じ |
| 5. 評価の誤りか（一覧 §3） | 市場で実際に得た利益 | 競技規約 §4 の計算規則と異なる誤りに気づいたうえで、自他の評価額や順位を歪めること |
| 6. 対象内でも禁止（競技規約 §8・参加規約 第15条） | 上の 5 本を満たす通常の攻撃 | 自己取引による利益移転、評価価格の操作、非公開シナリオの探索、チーム間の共謀、競技中の人為的介入、複数の参加単位への参加 |

## Q. 有効な攻撃にはどのようなものがあるか

venue ごとの例です。いずれも、プロトコルの仕様どおりの動作を前提とし、コストかリスクを負って得る優位です。網羅ではなく、ここに無い行為も 6 本の線で判定します。

**AMM（Uniswap V3・Balancer v2・Curve）**

- venue 間、または参照価格との乖離を取る裁定
- 薄い流動性に対する大口での価格移動と、それによる他のエージェントや環境フローへの不利な約定
- 採掘済みの情報からの順序予測による先回り。pending は見えないので、mempool を読む型のサンドイッチは成立しない
- LP としての手数料取り、レンジの操作
- フラッシュローンなど、仕様どおりの機能の利用
- Factory 経由で欺瞞的なプールやトークンを作り、他のエージェントを誘い込むこと（効果が不利な取引・資産の損失にとどまる範囲）

**Aave v3**

- 他のエージェント、victim、環境の建玉の清算。清算ボーナスの奪い合い
- 1 ブロック遅れのオラクルを前提にした、清算タイミングの先取り
- 預入と借入で利用率と金利カーブを動かし、他のエージェントの借入コストを上げること
- 取引で価格を動かして他のエージェントの HF を下げ、清算に追い込むこと
- フラッシュローンの利用

**GMX v2**

- 偏った OI に対する funding の取り方、相手の建玉と逆方向のポジション
- 注文の執行と清算は環境の keeper が行うので、参加者が GMX の清算人になることはできない

**LST（ステーキング Vault と LST/WETH 市場）**

- 二次市場のディスカウントと償還レートの差を取る裁定
- 大口の出金でキューを混雑させ、他のエージェントの退出コストを上げること

**Liquity（eUSD）**

- 償還で最下位 ICR の Trove から担保を奪うこと（他のエージェントの Trove を含む）
- 清算と、Stability Pool での担保の取得
- Trove の開き方で TCR を下げて Recovery Mode を誘発し、他のエージェントの Trove を清算対象にすること
- sorted list 上で相手より前に債務を置き、償還を相手に向けること
- デペグの買いと償還

**市場価格の stable（DAI・eUSD）**

- ペグ乖離の裁定、環境の買い戻しの相手方になること

**他の参加単位のエージェント**

- 相手が読みに来るチェーン上のデータ（取引パターン、ログ、トークン名、プールの状態）を通じて、判断を誤らせること
- 相手が配置したコントラクトの欠陥（正直だがバグのある vault など）からの資産の取得
- 相手が自分のコントラクトに与えた承認を使った引き出し
- 公式レジーム（agentMarkets 有効）では、自分が配置したコントラクトが MarketRegistry 経由で全員に公開されるので、罠コントラクトの設置が成立する。練習環境には registry が無いので、相手が自力で Factory を見ている場合にしか届かない

**環境の建玉・注文・イベント**

- 背景フローや whale 注文の相手方として約定すること、victim の清算、デペグ窓での環境の売買の相手方になること
- レジーム 7（launch）と 11（vuln）で途中に出現するプールの売買。rigged なプールの見極めは参加者の責任

## Q. 無効な攻撃にはどのようなものがあるか

一覧 §3 の対象外と、競技規約 §8・参加規約 第15条の禁止行為です。

| 区分 | 具体例 |
|---|---|
| オラクルへの書き込み | PriceFeed、Aave の aggregator、GMX の oracle provider、Liquity の価格アダプターへの書き込み。読むのは可 |
| 主催者の役割に限られた関数 | Aave の POOL_ADMIN と PoolConfigurator、GMX の CONFIG_KEEPER・注文の執行・清算、ステーキング Vault の owner の setRewardRate と slash、MarketRegistry への登録 |
| SimpleLending | 市場の作成・供給・借入・清算を含む利用の全般。registry の `verified: true` は許可ではない |
| Aave の試験用 Faucet とトークン | 受け取り、担保や借入への利用 |
| 環境ウォレット | 鍵の推定・導出と署名、承認や権限の欠陥を使った参加者自身の署名による資産の取得 |
| 上流に共通する脆弱性 | 6 プロトコル本体のコードの欠陥。参加者が複製して配置した場合も同じ。見つけたら一覧 §6 で報告 |
| 無から作る・ノーリスクで奪う | 権限の無い mint、所有者チェックの漏れた引き出しなど環境側の欠陥。他者の資産を凍結するだけの欠陥。ガス代は対価にならない |
| 評価の誤り | 採点アダプタの穴による評価額の水増し、他者の過小評価。気づいたら止めて報告。気づく前の分は再計算のみ |
| プロセスへの干渉 | エージェントのプロセス・コンテナ・推論プロキシへの直接の干渉。トークン名やログに文字列を置いて、コードの実行・停止・鍵の取得・外部通信を誘導すること |
| 主催者の設備 | RPC ゲートウェイ、`anvil_*` や `evm_*` などの操作 API、coordinator、推論プロキシ、ダッシュボード。大量のリクエスト、ガス予算（10M）の超過、コントラクトの name・symbol・log を読む経路を使った攻撃も含む |
| 競技環境の外 | 実ネットワーク、第三者のサービス、他の参加者の開発環境・機器・認証情報 |
| 対象内でも禁止 | 自分の参加単位の間や共謀相手との利益移転、採点断面を狙った評価価格の操作、非公開シナリオの探索、競技中の人為的介入、名義を変えた複数参加 |

## Q. 判断が割れやすい境界はどこか

- 採点の境界付近で価格を動かす行為は、競技規約 §8 の「評価価格の操作」（意図が要件）と通常の取引の境界にあります
- 他のエージェントの承認を使った引き出しは、相手の判断の弱点として対象内です。環境ウォレットの承認を使うと対象外です
- 実在プロトコルの欠陥、評価の誤り、無から作る欠陥の 3 つは、2026年10月20日発効の競技規約 §8 改定までは一覧による対象外にとどまります。それ以前の行為への措置は、参加規約 第15条など既存の条項に該当する場合だけです

## Q. 一覧の対象外にある不具合を見つけたらどうするか

- 利用せずに、Discord で運営に DM で報告してください（参加規約 第14条第4項）
- 善意で合理的に報告した参加者を、その報告だけを理由に不利に扱うことはありません
- 実在プロトコルの欠陥については、上流への開示と報酬の受け取りは報告者に委ねられます。主催者は報告者の同意なく上流へ開示しません

## Q. 一覧は変わるか

- 変更は一覧のページに掲載して行い、内容と日付が記載されます
- 対象を狭める変更も広げる変更も、効力発生日の 14 日前までに掲載されます。提出凍結後は、対象を狭めることも広げることもありません
- アドレスの追記や名称の訂正のような、範囲を変えない補完はいつでも行われます
