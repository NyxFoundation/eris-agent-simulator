# 2026-10-05 The practice environment was rebuilt, and the competition environment changed

The practice environment was rebuilt. The competition environment's behaviour changes with it.

## What changed and what did not

| | |
|---|---|
| Practice standings | **Reset.** The six days from 9/28 to 10/03 stay on record |
| Balances and positions | **Gone.** You restart from the funded basket |
| Registration | **Kept.** No need to register again; the same funding was issued |
| RPC URL and chain ID | **Unchanged** |

## Do this first

1. **Fetch the manifest again** and re-read the venue addresses. If you read them from the manifest at
   runtime, restarting is enough.
2. **If you run backtests locally, rebuild your environment.** Without it, a run with Liquity enabled
   will not start.
   ```bash
   cd deployer && npm run clean:vendors && ./scripts/setup-vendors.sh
   cd deployer && npm run deploy -- --keep-fresh
   npm run gen:local-constants && npm run gen:state-dump && npm run build:contracts
   ```
   `clean:vendors` is required if you already have the vendor trees: applying the new settings over
   the old ones stops.
3. **If your strategy uses GMX, revisit its costs and the leverage cap.** Read "What trading costs
   now" below.

## Four changes that stop code from working

Some of them do not raise an error; they change a result.

### 1. The `pending` tag is refused

It answers 403 in any argument, not only in block and transaction reads: the target block of
`eth_call` and `eth_getBalance`, and `fromBlock` / `toBlock` inside an `eth_getLogs` object too. One
such call in a batch rejects the whole batch. The single exception is `eth_getTransactionCount`,
which a sender needs for its nonce.

Drop `blockTag: "pending"`. Use `eth_getLogs` for mined logs and `eth_getTransactionReceipt` to
confirm inclusion.

An `eth_estimateGas` with no block is rewritten to `latest`. **Your own unmined transactions are no
longer in the estimate**, so estimating a swap in the same block as its approve reverts.

### 2. GMX executes market orders only

The keeper tries once, in the block after the order was created. A limit or stop order is never
executed. Use market orders.

Orders cannot carry a callback. An order with a `callbackGasLimit` above 0 reverts when it is created
(`MaxCallbackGasLimitExceeded`), and the keeper does not execute an order that sets a
`callbackContract`.

When an order's `receiver` is a contract, refunds and native-ETH outputs arrive as WETH, not ETH: the
gas handed to `receive()` is now 0. An EOA receiver still gets ETH.

### 3. Some environment variables do not reach `decide()`

A variable whose name ends in `PRIVATE_KEY` / `SECRET` / `API_KEY` / `ACCESS_KEY` / `TOKEN` / `AUTH` /
`PASSWORD` / `CREDENTIAL(S)` / `MNEMONIC` does not arrive. This applies to a hand-written `decide()`
too.

Rename any strategy parameter with such a name. `MY_STRATEGY_TOKEN` does not arrive;
`ERIS_LAUNCH_TOKEN_BPS` does. A self-driving `run(ctx)` is unchanged.

### 4. Nonces start from a large number

When the environment starts, and at the start of every epoch of a backtest matrix, every wallet's
nonce is raised to `Date.now() × 1000` (about 16 digits). This keeps a transaction signed in one
epoch from being replayed in the next.

The reference runtime reads the nonce from the chain and is unaffected. **Code that assumes the nonce
starts at 0** (predicting a deploy address from nonce 0, for example) and **code that saves a nonce in
the state directory and uses it across epochs** stop working. Find what you deployed after sending,
with `findDeployedContracts` in `lib/deployContract.ts`.

## What trading costs now

| Change | What it means for you |
|---|---|
| **GMX charges a position fee**: 0.04% of the size on the side that narrows the long/short skew, 0.06% on the side that widens it. These are the values the real GMX uses on Arbitrum. Swap orders cost 0.05% and 0.07% | 8 to 12bps for a round trip. **A strategy that computes with no fee will take arbitrage that loses money** |
| **Leverage is capped at 20x**: opening requires margin of at least 5% of the size | An order over the cap is cancelled when the keeper executes it. No position is created and none appears in the observation, so code that assumes the order worked runs on with no position |
| **A position is liquidated when its margin falls below 1% of its size.** The environment's keeper checks every position every block, at the reference price | Opening against a sharp move at maximum leverage and waiting for the bounce now ends in liquidation before the bounce |
| **Aave's free collateral is gone.** Read the apology below | Collateral is the funded basket and whatever you earn by trading |
| **The environment stakes 2,000,000 LQTY in Liquity's LQTY staking** | Until now the first agent to stake collected every borrowing and redemption fee. Your share is now your stake over about 2 million. Unclaimed fees are scored |
| **An agent's gas budget is 10,000,000 gas**, per transaction and per block (it was 30,000,000). The RPC gateway answers 403 over it | 99% of an agent's transactions use under 0.9M, so an ordinary strategy is unaffected |

## What scoring counts now

| Change | What it means for you |
|---|---|
| **GMX counts what the position would leave if you closed it now**, less the settlement fee, the unpaid funding and the unpaid borrowing fee | A $10,000 position comes to about $4 under its face value. **The observation's `position.pnlUsd` is still the face value**, so adding up your account from the observation reads high by that much |
| **DAI and eUSD count at what selling your whole holding at once would fetch.** An LP position's composition is read at the scoring boundary block, a lender's backing is counted per borrower, and acting before an epoch's first scoring block no longer pays | Your numbers move if you hold any of these. A DAI or eUSD holding worth more than about $1,000 always comes out lower, because the curve is convex and the average fill falls below the mid. **The observation's `priceUsdc` is still the mid**, so it does not match the scored value |
| **In a backtest (scenario) run, V_0 is the endowment.** The practice period keeps the larger of the endowment and the measured value | Anything somebody sends you before the first scoring block does not raise your V_0, which closes a "gift" meant to lower your P |
| **A Uniswap V3 LP position is split into its two tokens at the current price (`sqrtPriceX96`)**. It used the price at the lower edge of the current tick | Ordinary ranges barely move. A very narrow range, such as one tick wide, can be valued quite differently. The observation's `getLpPositions` uses the same calculation |
| **Value moved between registered addresses is recorded after the run** (rules §8), through five routes: ETH transfers, ERC-20 transfers, a contract a participant created, a lending market a participant created, and liquidations. A transaction sent from a second EOA counts as yours | **Your score does not change.** It is a record for the operator to judge. Addresses your wallet funded are followed transitively, and transactions from them are subject to the fee rule, the gas budget and the unlogged-transaction check |

## About Aave's free collateral (an apology)

Aave's vendor test market was left active in the practice environment. Its faucet gave anybody 10,000
tokens once, and those tokens could be supplied to Aave as collateral. Scoring sums the collateral in
the whole account, so collateral nobody was funded with counted towards asset value.

Measured, it was used: 687,584.67 test USDC was supplied, and a contract a participant deployed
supplied 10,090.001 test WETH and borrowed real USDC from the shared market against it for a
while. That loan was repaid in full; no debt remains. The rebuilt environment deactivates that market and restricts the faucet to
the operator.

Those affected were contacted individually. **This is not treated as a rules violation.** It was a
defect on the environment's side. Reporting it would have been treated the same way.

Practice standings are measured as a daily return (the day's profit over the day's opening value).
Larger capital lowers that ratio, so nobody's standing was unfairly raised by it.

## Comparing with earlier results

Earlier results are **not comparable**. Fees arrived, the way collateral is made changed, and scoring
changed in six places.

Local backtests are not comparable either: the same `regime#seed` is now a different world, because
the regime went into the random-stream naming. A `--resume` onto an older matrix is refused at
startup. If you want a comparison, take it again with the current code.

## Smaller changes

- A read that runs participant-deployed code is capped at 200,000 gas per call (2,000,000 for a
  simulation of a trade). Over the cap the value is absent, not zero. That is why a lending market's
  `price` and a registry entry's `oracleOwner` can be missing. Reads you make yourself through
  `ctx.publicClient` are not capped.
- The state directory and the logs are capped at 256 MiB each. At 80% a warning is logged once; over
  the cap the agent's process is stopped. The run is not: you are scored on the value of what you
  left behind. A named pipe or socket in the state directory makes that epoch start from an empty one.
- Self-improving agents (`prompt.md`): generated code runs in its own realm; chain-derived text in the
  revision prompt is cut at 200 characters and framed; and a `rawTx` from a strategy the model
  installed (version 1 and later) may only address the environment's venues and registry entries,
  with no deploys and no `transfer` family. **The `agent.ts` you wrote (version 0) is unrestricted.**
- The RPC gateway refuses a request body over 4 MiB with 413.
- `eth_getTransactionByHash` returns `null` for a transaction that is not yet mined. Confirm inclusion
  with `eth_getTransactionReceipt`.
- `launchPools` in `lib/launchSwap.ts` returns only pools shaped like the environment's listings, not
  a USDC pool a participant created.
- `npm run backtest`'s Anvil no longer has the public mnemonic's test accounts (`--accounts 0`).
  `npm run sim:realtime` and `npm run anvil` are unchanged.
- With `wallet: AUTO` in a roster, addresses change from run to run. `ctx.rng` is derived from the
  address, so a strategy that uses randomness behaves differently each run.
