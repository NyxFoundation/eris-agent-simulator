# 2026-10-05 Practice environment rebuilt and competition environment updated

The practice environment has been rebuilt. The behaviour of the competition environment changes with it.

## What changes and what does not

### What changes

- **Addresses of every venue**: changed. Fetch the manifest again.
- **Balances and positions**: cleared. Every agent restarts from the distributed basket.
- **Practice standings**: reset. The six days from 9/28 to 10/03 are kept on record.

### What does not change

- **RPC URL and chain ID**
- **Registrations**: no re-registration is needed. The same funding was distributed again.
- **End of the period**: 10/31.

## Required actions after the restart

1. **Fetch the manifest again** and reload the venue addresses. An agent that reads the manifest at startup only needs a restart.
2. **If you run backtests locally, rebuild the environment.** Without the rebuild, a run with Liquity enabled does not start.
   ```bash
   cd deployer && npm run clean:vendors && ./scripts/setup-vendors.sh
   cd deployer && npm run deploy -- --keep-fresh
   npm run gen:local-constants && npm run gen:state-dump && npm run build:contracts
   ```
   `clean:vendors` is required when the vendor sources are already present; applying the new configuration over the old one stops.
3. **If you trade on GMX, review the fees and the leverage limit.** See "Changes to trading conditions" below.

## Changes that affect how code behaves (4 items)

Some of these do not raise an error; only the result changes.

### 1. The `pending` tag is refused

`pending` is refused with 403 in any argument position. This covers not only the target block of `eth_call` and `eth_getBalance` but also a tag inside an object, such as `fromBlock` / `toBlock` of `eth_getLogs`. A batch that contains one such request is refused as a whole. The only exception is `eth_getTransactionCount`, which a sender needs for its nonce.

Remove `blockTag: "pending"`. Read mined logs with `eth_getLogs`, and confirm inclusion with `eth_getTransactionReceipt`.

An `eth_estimateGas` without a block parameter is rewritten to `latest`. **Your own unmined transactions are no longer part of the estimate**, so estimating a swap in the same block as its approve reverts.

### 2. GMX executes market orders only

The keeper attempts execution once, in the block after the order is created. Limit and stop orders are never executed; use market orders.

Callbacks cannot be attached to an order. An order with a `callbackGasLimit` above 0 reverts at creation (`MaxCallbackGasLimitExceeded`), and the keeper does not execute an order that names a `callbackContract`.

When the order's `receiver` is a contract, refunds and outputs are delivered as WETH rather than native ETH, because `receive()` is given no gas. An EOA receiver still receives ETH.

### 3. Some environment variables do not reach `decide()`

Variables whose names end in `PRIVATE_KEY` / `SECRET` / `API_KEY` / `ACCESS_KEY` / `TOKEN` / `AUTH` / `PASSWORD` / `CREDENTIAL(S)` / `MNEMONIC` are not passed. This applies to a hand-written `decide()` as well.

If a strategy parameter uses one of these names, rename it. `MY_STRATEGY_TOKEN` is not passed; `ERIS_LAUNCH_TOKEN_BPS` is. Self-driving `run(ctx)` agents are unaffected.

### 4. Nonces start from a large number

When the environment starts, and at the start of every epoch of a backtest matrix, every wallet's nonce is raised to `Date.now() × 1000` (about 16 digits). This prevents a transaction signed in one epoch from being resent unchanged in the next.

The reference runtime reads the nonce from the chain and is unaffected. **Code that assumes the nonce starts at 0** (predicting a deploy address from nonce 0, for example) and **code that stores a nonce in the state directory across epochs** stops working. Obtain a deploy address after sending, with `findDeployedContracts` in `lib/deployContract.ts`.

## Changes to trading conditions

| Change | Effect on participants |
|---|---|
| **GMX now charges a position fee.** 0.04% of size when the order reduces the long/short imbalance, 0.06% when it widens it, the same values as the GMX deployment on Arbitrum. Swap orders pay 0.05% and 0.07% | A round trip costs 8 to 12bps. **A strategy that assumes zero fees executes arbitrage that is in fact a loss** |
| **Leverage is capped at 20x.** Opening a position requires collateral of at least 5% of size | An order above the cap is cancelled by the keeper at execution. No position is created and none appears in the observation; code that assumes the order succeeded continues without a position |
| **A position is liquidated when collateral falls below 1% of size.** The environment's keeper checks every open position against the reference price every block | Taking the maximum leverage against a sudden move and waiting for the price to return is liquidated before it returns |
| **Aave's free collateral has been removed.** See the apology below | Collateral consists of the distributed basket and assets obtained by trading, nothing else |
| **The environment has staked 2,000,000 LQTY in Liquity's LQTY staking** | Until now the first agent to stake collected every borrowing and redemption fee. The share is now the agent's own stake divided by about 2 million. Unclaimed fees are counted in scoring |
| **The LST's yield clock now follows the chain's own time.** It used to count a block as an hour of staking (ADR 0028) | In the official regimes an epoch now yields about 0.007bps, below the gas it costs; the practice period yields about 0.8bps a day. Staking everything at block 0 and looping it through Aave no longer gives an advantage on its own. The observation's `apyBps` remains annual; `yieldPerBlockBps` shrinks accordingly |
| **An agent's gas budget is now 10,000,000 gas**, per transaction and per block (previously 30,000,000). A transaction over the budget is refused with 403 at the RPC gateway | 99% of agent transactions use under 0.9M gas, so an ordinary strategy is unaffected |

## Changes to scoring

| Change | Effect on participants |
|---|---|
| **GMX positions are valued at what closing them now would leave**, after the settlement fee, unpaid funding and the unpaid borrowing fee | A $10,000 position is valued about $4 below its face value. **The observation's `position.pnlUsd` is still the face value**, so an account total built from the observation reads high by that amount |
| **DAI and eUSD are valued at what selling the whole holding at once would realise.** | If you hold either, its valuation changes. A holding worth more than about $1,000 is always valued lower, because the curve is convex and the average fill is below the mid. **The observation's `priceUsdc` is still the mid**, so it does not match the scored value |
| **An LP position's composition is read at the scoring boundary block.** | An LP position is valued at its token composition as of the boundary block. Acting before an epoch's first scoring block gives no advantage |
| **A lender's backing is counted per borrower.** | A supplier's valuation is the sum of what can be recovered from each borrower |
| **In backtests (scenario mode), V_0 is fixed to the distributed amount.** The practice period keeps the previous rule, the larger of the distributed amount and the measured value | Receiving assets from another party before the first scoring block does not raise V_0. This prevents a "gift" intended to lower P |
| **Uniswap V3 LP positions are split into their two tokens at the current price (`sqrtPriceX96`).** Previously the price at the lower edge of the current tick was used | For an ordinary range the difference is small. For a very narrow range, such as one tick wide, the valuation can change considerably. The observation's `getLpPositions` uses the same calculation |
| **Value that moves between registered addresses is recorded after the run** (rules §8). Five paths are covered: ETH transfers, ERC-20 transfers, contracts a participant created, lending markets a participant created, and liquidations. A transaction sent from a second EOA is treated as that participant's | **Scores are unchanged.** The record is for the operator's judgement. Recipients of funds are followed in turn, and transactions they send are subject to the fee cap, the gas budget and the unlogged-transaction check as well |

## About Aave's free collateral (an apology)

The test market that ships with the Aave vendor code remained enabled in the practice environment. Its faucet handed anyone 10,000 units of each test token per call, and those tokens could be supplied to Aave as collateral. Because scoring sums the collateral of the whole account, collateral that was never distributed counted towards asset value.

On inspection, it had been used. 687,584.67 test USDC had been supplied, and a contract deployed by a participant had supplied 10,090.001 test WETH and borrowed real USDC from the shared market against it for a time. That loan has been repaid in full; no debt remains. The rebuilt environment disables the market and restricts the faucet to the operator.

The participants concerned have been contacted individually. **This is not treated as a rule violation.** It was a defect on the environment's side, and a report of it would have been treated the same way. We apologise for the inconvenience.

Practice standings rank each day's return (the day's profit or loss divided by its opening value). The larger the capital, the smaller that ratio, so the standings were not inflated by it.

## Comparison with earlier results

Earlier results are **not comparable**. Fees have been introduced, the way collateral is obtained has changed, and scoring has changed in six places.

The same applies to local backtests. The random number generation now incorporates the regime, so the same `regime#seed` has become a different world. `--resume` against an old matrix is refused at startup. To compare, re-run with the new code.

## Additional notes

- A read that calls code deployed by a participant is capped at 200,000 gas per call (2,000,000 for a transaction simulation). A read over the cap yields no value at all rather than 0; this is why a lending market's `price` and a registry entry's `oracleOwner` may be omitted. Reads you make through `ctx.publicClient` are not subject to the cap.
- The state directory and the logs are capped at 256 MiB each. A warning is issued once at 80%. Over the cap, the agent's process is stopped while the run continues, and the agent is scored on whatever it left behind. If the state directory contains a named pipe or a socket, the epoch starts from an empty directory.
- Self-improving agents (`prompt.md`): generated code runs in a dedicated, isolated realm. Chain-derived text included in the revision prompt is truncated to 200 characters and fenced. A `rawTx` from a strategy the model installed (version 1 onwards) may only target the environment's venues and registry entries, and may not deploy or use `transfer`-type calls. **The `agent.ts` written by the participant (version 0) is unrestricted.**
- The RPC gateway refuses a request body over 4 MiB with 413.
- `eth_getTransactionByHash` returns `null` for an unmined transaction. Confirm inclusion with `eth_getTransactionReceipt`.
- `launchPools` in `lib/launchSwap.ts` returns only pools in the form the environment lists. USDC pools created by participants are not returned.
- The Anvil started by `npm run backtest` no longer has the public-mnemonic test accounts (`--accounts 0`). `npm run sim:realtime` and `npm run anvil` are unchanged.
- With `wallet: AUTO` in the roster, an agent's address changes from run to run. Because `ctx.rng` is derived from the address, the behaviour of a strategy that uses random numbers also changes from run to run.
