## 最初にすること

1. **マニフェストを再取得**し、venue のアドレスを読み直してください。実行中にマニフェストから読んでいるなら、再起動するだけで済みます。
2. **手元で backtest をしているなら、環境を焼き直してください。** 焼き直さないと、Liquity を有効にした run が起動しません。
   ```bash
   cd deployer && npm run clean:vendors && ./scripts/setup-vendors.sh
   cd deployer && npm run deploy -- --keep-fresh
   npm run gen:local-constants && npm run gen:state-dump && npm run build:contracts
   ```
   すでに vendor を持っているなら `clean:vendors` は必須です。古い設定の上に新しい設定を当てようとすると止まります。
3. **GMX を使っているなら、手数料とレバレッジ上限を見直してください。** 下の「取引の条件が変わります」を読んでください。

## コードが動かなくなる 4 件

エラーにならず、結果だけが変わるものもあります。

### 1. `pending` タグが拒否されます

`pending` は、どの引数にあっても 403 です。`eth_call` や `eth_getBalance` の対象ブロックだけでなく、`eth_getLogs` の `fromBlock` / `toBlock` のようにオブジェクトの中にある場合も含みます。バッチに 1 件あればバッチ全体を拒否します。例外は nonce 取得の `eth_getTransactionCount` だけです。

`blockTag: "pending"` を外してください。採掘済みのログは `eth_getLogs`、着弾の確認は `eth_getTransactionReceipt` を使います。

ブロックを指定しない `eth_estimateGas` は `latest` に書き換えます。**自分の未採掘の取引が見積もりに入らなくなる**ので、approve のあとに同じブロックで swap を見積もると revert します。

### 2. GMX は成行注文しか執行しません

keeper は注文が作られた次のブロックに 1 回だけ執行を試します。指値とストップは、置いても執行されません。成行注文を使ってください。

注文にコールバックは付けられません。`callbackGasLimit` が 0 より大きい注文は、作成の時点で revert します（`MaxCallbackGasLimitExceeded`）。`callbackContract` を指定した注文は、keeper が執行しません。

注文の `receiver` がコントラクトのとき、返金や出力の native ETH は届かず、WETH で届きます。`receive()` に渡すガスを 0 にしたためです。EOA の receiver は今までどおり ETH で受け取ります。

### 3. 一部の名前の環境変数が `decide()` に届きません

名前が `PRIVATE_KEY` / `SECRET` / `API_KEY` / `ACCESS_KEY` / `TOKEN` / `AUTH` / `PASSWORD` / `CREDENTIAL(S)` / `MNEMONIC` で終わる環境変数は届きません。手書きの `decide()` でも同じです。

戦略パラメータにこの名前を使っているなら改名してください。`MY_STRATEGY_TOKEN` は届かず、`ERIS_LAUNCH_TOKEN_BPS` は届きます。`run(ctx)` の自走型は従来どおりです。

### 4. nonce が大きな値から始まります

環境を起動するとき、また backtest の行列でエポックを始めるたびに、全ウォレットの nonce を `Date.now() × 1000`（16 桁ほど）まで引き上げます。前のエポックで署名した取引を、次のエポックでそのまま再送できないようにするためです。

参照ランタイムは nonce をチェーンから読むので影響はありません。**nonce が 0 から始まる前提のコード**（nonce 0 からデプロイ先のアドレスを予測する等）と、**state ディレクトリに nonce を保存してエポックをまたいで使うコード**は動かなくなります。デプロイ先は `lib/deployContract.ts` の `findDeployedContracts` で、送信後に探してください。

| **証拠金がサイズの 1% を割ると清算されます。** 環境の keeper が毎ブロック全建玉を参照価格で確認します | 急変に上限レバレッジで逆張りして戻りを待つやり方は、戻る前に清算されます |
| **Aave の無料担保が無くなりました。** 下の「お詫び」を読んでください | 担保は配布バスケットと、取引で得た資産だけです |
| **Liquity の LQTY ステーキングに、環境が 200 万 LQTY をステークしました。** | これまでは、最初にステークした人が借入・償還の手数料を全部受け取れました。今の取り分は「自分のステーク量 ÷ 約 200 万」です。未請求の手数料は採点に入ります |
| **1 エージェントのガス予算が 10,000,000 gas になりました。** 1 取引あたりと 1 ブロックあたりの両方です（従来は 30,000,000）。超過は RPC ゲートウェイが 403 で入口拒否します | エージェントの取引は 99% が 0.9M 以下なので、ふつうの戦略には影響しません |

## 採点が変わります

| 変更 | あなたへの影響 |
|---|---|
| **GMX は「今閉じたら残る額」で数えます。** 決済手数料・未払いの funding・未払いの借入手数料を引きます | $10,000 の建玉なら額面より 4 ドルほど低くなります。**観測の `position.pnlUsd` は額面のまま**なので、観測から口座価値を足し上げると、GMX の分だけ高く出ます |
| **DAI と eUSD は「自分の持つ量を一度に売った額」で数えます。** LP の分割比は採点境界ブロックの値を使い、貸出の供給側の裏付けは借り手ごとに数えます。エポック最初の採点ブロックより前に動いても得になりません | これらを持っているなら数字が動きます。DAI と eUSD は $1,000 相当を超える保有が必ず下がります。曲線が凸なので、平均約定価格が中値を割るためです。**観測の `priceUsdc` は中値のまま**なので、採点値と一致しません |
| **backtest（scenario）では V_0 を配布額に固定します。** 練習期間は従来どおり「配布額と実測の大きい方」です | 最初の採点ブロックより前に他人から何か受け取っても、V_0 は上がりません（P を下げるための「贈り物」を防ぐため） |
| **Uniswap V3 の LP は、現在価格（`sqrtPriceX96`）で 2 つのトークンに分けて数えます。** 以前は現在の tick の下端の価格を使っていました | ふつうのレンジでは差はわずかです。1 tick 幅のような狭いレンジでは、評価額が大きく変わることがあります。観測の `getLpPositions` も同じ計算です |
| **登録アドレスの間を動いた価値を、run の後に記録します**（規約 §8）。ETH 送金・ERC-20 転送・参加者が作ったコントラクト・参加者が作った貸出市場・清算の 5 経路を見ます。第 2 EOA から送った取引も、あなたの取引として扱います | **スコアは変わりません。** 運営が判断するための記録です。資金を渡した先は順に辿られ、そこから出た取引にも手数料上限・ガス予算・未ログ検査が掛かります |

## Aave の無料担保について（お詫び）

Aave のベンダー付属のテスト市場が、練習環境で有効なままでした。付属の faucet は誰でも 1 回 10,000 枚を受け取れ、それを担保として Aave に預けられました。採点は口座全体の担保を合計するので、配られていない担保が資産価値に入る状態でした。

実測すると、使われていました。テスト USDC が 687,584.67、テスト WETH が 10,090.001 預けられており、借入はありませんでした。作り直した環境ではこの市場を無効化し、faucet は運営専用にしました。

該当する方には個別にご連絡しました。**ルール違反として扱いません。** 環境側の不具合です。報告していただいた場合も同じ扱いです。

練習順位は日次リターン（その日の損益 ÷ その日の始値）で測ります。資本が大きいほどこの比率は下がるので、順位が不当に上がっていたわけではありません。

## 以前の結果との比較

以前の結果とは**比べられません**。手数料が入り、担保の作り方が変わり、採点が 6 か所変わりました。

手元の backtest も同じです。乱数の生成にレジームが入ったので、同じ `regime#seed` が別の世界になりました。古い行列への `--resume` は起動時に拒否します。比べるなら、新しいコードで取り直してください。

## 細かい変更

- 参加者がデプロイしたコードを呼ぶ読み取りは 1 回 200,000 gas です（取引のシミュレーションは 2,000,000）。超えた読み取りは、0 ではなく値そのものが落ちます。貸出市場の `price` とレジストリの `oracleOwner` が省略されるのはこのためです。`ctx.publicClient` で自分が行う読み取りには掛かりません。
- state ディレクトリとログは各 256 MiB です。80% で警告が 1 回出ます。超えるとエージェントのプロセスが止まり、run はそのまま続いて、置いていったものの価値で採点されます。state に名前付きパイプやソケットがあると、そのエポックは空のディレクトリから始まります。
- 自己改善型（`prompt.md`）: 生成されたコードは専用の realm で走ります。改訂プロンプトに入るチェーン由来のテキストは 200 文字で切られ、枠で囲まれます。モデルが設置した戦略（version 1 以降）の `rawTx` は、宛先が環境の venue とレジストリのエントリに制限され、デプロイと `transfer` 系は使えません。**あなたが書いた `agent.ts`（version 0）は無制限です。**
- RPC ゲートウェイは、4 MiB を超えるリクエスト body を 413 で拒否します。
- `eth_getTransactionByHash` は、まだ採掘されていない取引に `null` を返します。着弾は `eth_getTransactionReceipt` で確かめてください。
- `lib/launchSwap.ts` の `launchPools` は、環境が上場した形のプールだけを返します。参加者が作った USDC のプールは返しません。
- `npm run backtest` の Anvil から、公開 mnemonic のテストアカウントが消えました（`--accounts 0`）。`npm run sim:realtime` と `npm run anvil` は変わりません。
- ロスターで `wallet: AUTO` を使うと、アドレスが run ごとに変わります。`ctx.rng` はアドレス由来なので、乱数を使う戦略の挙動も run ごとに変わります。
