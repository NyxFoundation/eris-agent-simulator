## 最初にすること

1. **マニフェストを再取得**し、venue のアドレスを読み直してください。実行中にマニフェストから読んでいるなら、再起動するだけで済みます。
2. **手元で backtest をしているなら、環境を焼き直してください。** 焼き直さないと、Liquity を有効にした run が起動しません。
   ```bash
   cd deployer && npm run clean:vendors && ./scripts/setup-vendors.sh
   cd deployer && npm run deploy -- --keep-fresh
   npm run gen:local-constants && npm run gen:state-dump && npm run build:contracts
   ```
   すでに vendor を持っているなら `clean:vendors` は必須です。古い設定の上に新しい設定を当てようとすると止まります。
3. **GMX を使っているなら、手数料とレバレッジ上限を見直してください。** 下の「取引の条件が変わります」を読んでください。

## コードが動かなくなる 3 件

エラーで止まるとは限りません。黙って結果が変わるものを含みます。

### 1. `pending` タグが拒否されます

どの引数にあっても 403 です。`eth_call` や `eth_getBalance` の対象ブロックだけでなく、`eth_getLogs` の `fromBlock` / `toBlock` のようにオブジェクトの中にある場合も含みます。バッチに 1 件あればバッチ全体を拒否します。例外は nonce 取得の `eth_getTransactionCount` だけです。

`blockTag: "pending"` を外してください。採掘済みのログは `eth_getLogs`、着弾の確認は `eth_getTransactionReceipt` を使います。

ブロックを指定しない `eth_estimateGas` は `latest` に書き換えます。**自分の未採掘の取引が見積もりに入らなくなる**ので、approve のあとに同じブロックで swap を見積もると revert します。

### 2. GMX は成行注文しか執行しません

keeper は注文が作られた次のブロックに 1 回だけ執行を試します。指値とストップは、置いても執行されません。注文の `callbackContract` も呼びません。成行に寄せてください。

### 3. 一部の名前の環境変数が `decide()` に届きません

名前が `PRIVATE_KEY` / `SECRET` / `API_KEY` / `ACCESS_KEY` / `TOKEN` / `AUTH` / `PASSWORD` / `CREDENTIAL(S)` / `MNEMONIC` で終わる環境変数は届きません。手書きの `decide()` にも効きます。

戦略パラメータにこの名前を使っているなら改名してください。`MY_STRATEGY_TOKEN` は届かず、`ERIS_LAUNCH_TOKEN_BPS` は届きます。`run(ctx)` の自走型は従来どおりです。

## 取引の条件が変わります

| 変更 | あなたへの影響 |
|---|---|
| **GMX に建玉手数料が入りました。** サイズの 0.04%（ロングとショートの偏りを縮める側）または 0.06%（広げる側）。本物の GMX（Arbitrum）と同じ値です。swap 注文は 0.05% と 0.07% | 往復で 8〜12bps です。**コストを 0 と見込んだ戦略は、赤字の裁定を打ちます** |
| **レバレッジの上限は 20 倍です。** 建てるときに証拠金がサイズの 5% 以上必要です | 超えた注文は keeper の執行でキャンセルされます。建玉が作られず観測にも現れないので、送った前提で動く戦略は建玉ゼロのまま走り続けます |
| **証拠金がサイズの 1% を割ると清算されます。** 環境の keeper が毎ブロック全建玉を参照価格で確認します | 急変に上限レバレッジで逆張りして戻りを待つ戦略は、建玉が生き残りません |
| **Aave の無料担保が無くなりました。** 下の「お詫び」を読んでください | 担保は配布バスケットと、取引で得た資産だけです |
| **1 エージェントのガス予算が 10,000,000 gas になりました。** 1 取引あたりと 1 ブロックあたりの両方です（従来は 30,000,000）。超過は RPC ゲートウェイが 403 で入口拒否します | 実測でエージェントの取引のガス使用量は 99% が 0.9M 以下なので、通常の戦略には影響しません |

## 採点が変わります

| 変更 | あなたへの影響 |
|---|---|
| **GMX は「今閉じたら残る額」で数えます。** 決済手数料・未払いの funding・未払いの借入手数料を引きます | $10,000 の建玉なら額面より 4 ドルほど低くなります。**観測の `position.pnlUsd` は額面のまま**なので、観測から口座価値を積み上げると GMX の分だけ高く出ます |
| **DAI と eUSD は「自分の持つ量を一度に売った額」で数えます。** LP の分割比は採点境界ブロックの値を使い、貸出の供給側の裏付けは借り手ごとに数えます。エポック最初の採点ブロックより前に動いても得になりません | 該当する保有があれば数字が動きます。DAI と eUSD は $1,000 相当を超える保有が必ず下がります。曲線が凸なので、平均約定価格が中値を割るためです。**観測の `priceUsdc` は中値のまま**なので、採点値と一致しません |
| **登録アドレスの間を動いた価値を、run の後に記録します**（規約 §8）。ETH 送金・ERC-20 転送・参加者が作ったコントラクト・参加者が作った貸出市場・清算の 5 経路を見ます。第 2 EOA から送った取引も、あなたの取引として扱います | **スコアは変わりません。** 運営が判断するための記録です。資金を渡した先は推移的に追跡され、そこから出た取引は手数料上限・ガス予算・未ログ検査の全部に掛かります |

## Aave の無料担保について（お詫び）

Aave のベンダー付属のテスト市場が、練習環境で有効なままでした。付属の faucet は誰でも 1 回 10,000 枚を受け取れ、それを担保として Aave に預けられました。採点は口座全体の担保を合計するので、配られていない担保が資産価値に入る状態でした。

実測すると、使われていました。テスト USDC が 687,584.67、テスト WETH が 10,090.001 預けられており、借入はありませんでした。作り直した環境ではこの市場を無効化し、faucet は運営専用にしました。

該当する方には個別にご連絡しました。**ルール違反として扱いません。** 環境側の欠陥であり、練習期間はそれを見つける場でもあります。報告していただいた場合も扱いは同じです。

なお練習順位は日次リターン（その日の損益 ÷ その日の始値）で測るため、水増しした資本はこの指標では不利に働いていました。順位が不当に上がっていたわけではありません。

## なぜ作り直したのか

9/28 に立てたチェーンでは、環境デーモンを再起動できませんでした。Liquity の手数料の受け取り先を運営が押さえる変更が入り、起動時にそれを検査するようになったのですが、その検査を稼働中のチェーンでは満たせません。LQTY の規約上、配布枠を持つアカウントは 1 年間ステークできないためです。

上の Aave の件も、稼働中のチェーンでは塞げません。参加者の建玉がそこに残っていると、塞いだ上でも起動検査が通らず、他人の建玉を運営は消せません。

作り直す以外の道がなく、順位のリセットはその帰結です。

## 以前の結果との比較

**比べられません。** 手数料が入り、担保の作り方が変わり、採点が 4 か所変わりました。

手元の backtest についても、同じ `regime#seed` が別の世界になりました。乱数の生成にレジームが入ったためです。古い行列への `--resume` は起動時に拒否されます。比べるなら、新しいコードで取り直してください。

## 当たった方だけが読むもの

- 参加者がデプロイしたコードを呼ぶ読み取りは 1 回 200,000 gas です（取引のシミュレーションは 2,000,000）。超えると値は 0 ではなく欠落します。貸出市場の `price` とレジストリの `oracleOwner` が省略されるのはこれが理由です。`ctx.publicClient` で自分が行う読み取りには掛かりません。
- state ディレクトリとログは各 256 MiB です。80% で警告が 1 回出て、超過するとエージェントのプロセスが止まります。run は止まらず、置いていったものの価値で採点されます。state に名前付きパイプやソケットがあると、そのエポックは空のディレクトリから始まります。
- 自己改善型（`prompt.md`）: 生成されたコードは専用の realm で走ります。改訂プロンプトに入るチェーン由来のテキストは 200 文字で切られ、枠で囲まれます。モデルが設置した戦略（version 1 以降）の `rawTx` は、宛先が環境の venue とレジストリのエントリに制限され、デプロイと `transfer` 系は使えません。**あなたが書いた `agent.ts`（version 0）は無制限です。**
- `npm run backtest` の Anvil から、公開 mnemonic のテストアカウントが消えました（`--accounts 0`）。`npm run sim:realtime` と `npm run anvil` は変わりません。
- ロスターで `wallet: AUTO` を使うと、アドレスが run ごとに変わります。`ctx.rng` はアドレス由来なので、乱数を使う戦略の挙動も run ごとに変わります。
