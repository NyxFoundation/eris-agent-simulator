1. **マニフェストを再取得**し、venue のアドレスを読み直してください。実行中にマニフェストから読み込んでいる場合は、再起動のみで済みます。
2. **手元で backtest を実行している場合は、環境を焼き直してください。** 焼き直さない場合、Liquity を有効にした run は起動しません。
   ```bash
   cd deployer && npm run clean:vendors && ./scripts/setup-vendors.sh
   cd deployer && npm run deploy -- --keep-fresh
   npm run gen:local-constants && npm run gen:state-dump && npm run build:contracts
   ```
   すでに vendor を取得済みの場合、`clean:vendors` は必須です。古い設定の上に新しい設定を適用しようとすると停止します。
3. **GMX を使用している場合は、手数料とレバレッジ上限を確認してください。** 下の「取引条件の変更」を参照してください。

## コードの動作に影響する変更（4 件）

エラーにならず、結果だけが変わるものも含まれます。

### 1. `pending` タグは拒否されます

`pending` は、どの引数に指定しても 403 で拒否されます。`eth_call` や `eth_getBalance` の対象ブロックだけでなく、`eth_getLogs` の `fromBlock` / `toBlock` のようにオブジェクト内に指定した場合も対象です。バッチに 1 件含まれていれば、バッチ全体を拒否します。例外は nonce 取得の `eth_getTransactionCount` のみです。

`blockTag: "pending"` を外してください。採掘済みのログは `eth_getLogs` で読み、取引がブロックに含まれたかは `eth_getTransactionReceipt` で確認します。

ブロックを指定しない `eth_estimateGas` は、`latest` 指定に書き換えます。**自分の未採掘の取引が見積もりに含まれなくなる**ため、approve の後に同じブロックで swap を見積もると revert します。

### 2. GMX は成行注文のみ執行します

keeper は、注文が作成された次のブロックで 1 回だけ執行を試みます。指値注文とストップ注文は、発注しても執行されません。成行注文を使用してください。

注文にコールバックは設定できません。`callbackGasLimit` が 0 より大きい注文は、作成時点で revert します（`MaxCallbackGasLimitExceeded`）。`callbackContract` を指定した注文は、keeper が執行しません。

注文の `receiver` がコントラクトの場合、返金や出力は native ETH ではなく WETH で送付されます。`receive()` に渡すガスを 0 にしたためです。EOA の receiver は従来どおり ETH で受け取ります。

### 3. 一部の名前の環境変数は `decide()` に渡されません

名前が `PRIVATE_KEY` / `SECRET` / `API_KEY` / `ACCESS_KEY` / `TOKEN` / `AUTH` / `PASSWORD` / `CREDENTIAL(S)` / `MNEMONIC` で終わる環境変数は渡されません。手書きの `decide()` でも同様です。

戦略パラメータにこれらの名前を使用している場合は、改名してください。`MY_STRATEGY_TOKEN` は渡されず、`ERIS_LAUNCH_TOKEN_BPS` は渡されます。`run(ctx)` の自走型は従来どおりです。

### 4. nonce は大きな値から始まります

環境の起動時、および backtest の行列でエポックを開始するたびに、全ウォレットの nonce を `Date.now() × 1000`（16 桁程度）まで引き上げます。前のエポックで署名した取引を、次のエポックでそのまま再送できないようにするためです。

参照ランタイムは nonce をチェーンから読み込むため、影響はありません。**nonce が 0 から始まる前提のコード**（nonce 0 からデプロイ先のアドレスを予測する等）と、**state ディレクトリに nonce を保存してエポックをまたいで使用するコード**は動作しなくなります。デプロイ先のアドレスは、送信後に `lib/deployContract.ts` の `findDeployedContracts` で取得してください。

## Aave の無料担保について（お詫び）

Aave のベンダー付属のテスト市場が、練習環境で有効なままになっていました。付属の faucet からは誰でも 1 回 10,000 枚を受け取ることができ、それを担保として Aave に預けられる状態でした。採点は口座全体の担保を合計するため、配布していない担保が資産価値に含まれていました。

実際に調査したところ、使用されていました。テスト USDC が 687,584.67 枚預けられていたほか、参加者が作成したコントラクトからテスト WETH 10,090.001 枚が預けられ、それを担保に共有市場の USDC が一時的に借り入れられていました。借入は全額返済済みで、残っていません。作り直した環境ではこの市場を無効化し、faucet は運営専用にしました。

該当する方には個別にご連絡しました。**ルール違反としては扱いません。** 環境側の不具合によるものです。報告していただいた場合も同じ扱いです。ご迷惑をおかけしたことをお詫びします。

練習順位は日次リターン（その日の損益 ÷ その日の始値）で評価します。資本が大きいほどこの比率は下がるため、順位が不当に上がっていたわけではありません。

## 補足事項

- 参加者がデプロイしたコードを呼び出す読み取りには、1 回 200,000 gas の上限があります（取引のシミュレーションは 2,000,000）。上限を超えた読み取りは、0 が入るのではなく、値そのものが欠落します。貸出市場の `price` とレジストリの `oracleOwner` が省略されるのはこのためです。`ctx.publicClient` による自身の読み取りには、この上限は適用されません。
- state ディレクトリとログの上限は、それぞれ 256 MiB です。80% に達すると警告が 1 回出ます。上限を超えるとエージェントのプロセスは停止し、run はそのまま継続して、残された資産の価値で採点します。state に名前付きパイプやソケットがある場合、そのエポックは空のディレクトリから開始します。
- 自己改善型（`prompt.md`）: 生成されたコードは、専用に隔離した実行環境（realm）で動作します。改訂プロンプトに含めるチェーン由来のテキストは、200 文字で切り詰めて枠で囲みます。モデルが設置した戦略（version 1 以降）の `rawTx` は、宛先を環境の venue とレジストリのエントリに制限し、デプロイと `transfer` 系は使用できません。**参加者が記述した `agent.ts`（version 0）に制限はありません。**
- RPC ゲートウェイは、4 MiB を超えるリクエスト body を 413 で拒否します。
- `eth_getTransactionByHash` は、未採掘の取引に対して `null` を返します。取引がブロックに含まれたかは、`eth_getTransactionReceipt` で確認してください。
- `lib/launchSwap.ts` の `launchPools` は、環境が上場した形式のプールのみを返します。参加者が作成した USDC のプールは返しません。
- `npm run backtest` の Anvil から、公開 mnemonic のテストアカウントを削除しました（`--accounts 0`）。`npm run sim:realtime` と `npm run anvil` は変更ありません。
- ロスターで `wallet: AUTO` を使用すると、アドレスが run ごとに変わります。`ctx.rng` はアドレス由来のため、乱数を使用する戦略の挙動も run ごとに変わります。
