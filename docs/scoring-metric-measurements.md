# 採点メトリクスの実測記録（issue #56 / ADR 0019）

**位置づけ**: ADR 0019 は*決定*の記録、この文書は*測定*の記録。数字が増えたらここを更新し、ADR は
決定そのものが変わったときだけ触る。両方に同じ表を置くと片方が腐るため、ADR からはここを指す。

**再現方法**（チェーン不要・再 run 不要。保存済みの epoch 系列から採点し直す）:

```
npm run metrics -- runs/<runDir> [runs/<runDir>...] [--lambda 0.25] [--rho 2] [--out metrics.json]
```

`summary.json` の `valueSeries.epochSeries`（境界ブロックと agent ごとの生の価値）を読み、
M1 / M4 / M7 / M9 / M13 を計算して、指標ごとの順位・M9 との食い違い・M27 Borda を出す。

## 1. ベンチマーク差し引きの実装漏れ（2026-08-13 に発見・修正）

カタログ M9 は `x_e` を**超過**対数リターンと定義しているが、ADR 0019 §1 の式には差し引きが無く、
実装もそれに従っていた。5 seed の実測でこれが露見した。

| | 生（差し引き無し） | 超過（M9 の定義） |
|---|---|---|
| peg-arb-eager | 0.281 | **0.358** |
| peg-arb | 0.111 | **0.241** |
| venue-arb | 0.051 | 0.070 |
| noop | 0.022（`std_e` 2.22e-4） | **0.000（`std_e` 厳密に 0）** |

（値は 5 seed の excess Sharpe = `mean_e/std_e` の平均）

**noop の `std_e` 2.22e-4 は peg-arb の全体 2.38e-4 の 93% を占めていた。**全員が持たされている
ガス予備 1 ETH が ETH 価格で動いていただけで、λ は agent のリスクではなく配布物のドリフトを測っていた。
差し引きを入れると peg-arb の `std_e` は 9.08e-5 に落ちる（残るのが本人のリスク）。

**この再採点に run のやり直しは要らなかった** — 生の境界価値を保存する設計（ADR 0017 §4 の
「生データから採点方法を差し替えられる」）の最初の配当。

## 2. 全候補指標での順位（b-harness 5 週、λ=0.25 / ρ=2）

M27 Borda（5 週の順位の合計。小さいほど上位）:

| 指標 | | | | |
|---|---|---|---|---|
| M1 Total PnL | eager=5 | **peg-arb=11** | venue-arb=17 | noop=17 |
| M4 超過対数成長 | eager=5 | **peg-arb=11** | venue-arb=17 | noop=17 |
| M7 MPPM (ρ=2) | eager=5 | **peg-arb=11** | venue-arb=17 | noop=17 |
| M13 Sharpe | eager=5 | **peg-arb=10** | noop=17 | venue-arb=18 |
| **M9 mean−λ·std** | eager=5 | **noop=12** | peg-arb=16 | venue-arb=17 |

**M9（λ=0.25）だけが「何もしない」を、確実に黒字の agent より上に置く。** 他の 4 指標は 5 週すべてで
peg-arb（週 +92〜+165 USDC）を noop の上に置き、M9 は 5 週中 3 週で下に落とす。M9 と他の指標は
**5 run 中 4 本で順位が食い違い**、食い違いは毎回この 1 点。

これは **ADR 0019 §4 の KPI（noop はまともな参加者の中位より下）を破っている**（4 体中 2 位 = 中位以上）。

## 3. λ 感度

seed ごとの excess Sharpe:

| agent | 801 | 802 | 803 | 804 | 805 | 最小 |
|---|---|---|---|---|---|---|
| peg-arb-eager | 0.333 | 0.330 | 0.378 | 0.389 | 0.361 | 0.330 |
| peg-arb | 0.174 | 0.251 | 0.237 | 0.245 | 0.300 | 0.174 |
| venue-arb | 0.152 | 0.199 | 0 | 0 | 0 | 0 |
| noop | 0 | 0 | 0 | 0 | 0 | 0 |

peg-arb の Sharpe が λ=0.25 をまたいでいる。λ を下げると素直に閉じる:

| λ | M9 の Borda | 週次 Sharpe 換算（`λ√41`） |
|---|---|---|
| 0.25 | eager=5, **noop=12**, peg-arb=16, venue=17 | 1.60 |
| 0.20 | eager=5, peg-arb=12, noop=14, venue=19 | 1.28 |
| **0.15** | eager=5, peg-arb=11, venue=17, noop=17（**M1 と完全一致**） | 0.96 |

**指標族の問題ではなく閾値の較正**。ただし ADR §4 の方針は「KPI が破れたらまず環境（イベント密度）を
直す」で、今の b-harness は 41 epoch に対しデペグ窓 3 つだけ（peg-arb が取引したのは 3〜5 epoch）。

## 4. funding の対照（120 ブロック × 2 本、同一 seed）

| | 初期価値 | ETH 比率 |
|---|---|---|
| 現行（`ethWei` 未設定 = 100 ETH + 25k USDC） | 325,016 | 92.3% |
| ADR §6（1 ETH + 100k USDC + `economicGas`） | 103,006 | 2.9% |

excess Sharpe:

| | eager | peg-arb | venue-arb | noop |
|---|---|---|---|---|
| 100 ETH + 25k | 0.725 | 0.523 | 0.399 | 0.000 |
| 1 ETH + 100k | 0.572 | 0.343 | 0.579 | 0.000 |

生のリターンで採点していた頃は前者が全員 −0.02 前後に潰れ、「現状の配布では λ が判別しない」と
読んでいたが、**それは funding ではなく差し引きの実装漏れの帰結だった**。§6 の funding を採る理由は
別にある（ベンチマークが 92% ETH だと「ベンチマークに対するリスク」と「リスク」が別物になる）。

`fundWallet` の `GAS_BUFFER_WEI = 5 ETH` は 2026-08-13 に畳み込み済み（それ以前は宣言値 +5 ETH が
配られていた。現行 funding の 105 ETH はこれ）。

## 5. 環境側の観察

- **venue-arb が 5 seed 中 3 本（803/804/805）で tx を 1 本も出していない**。スコアは noop と完全一致。
  λ の水準を決める証拠は実質 2 戦略にしか乗っていない
- **G7 は実際に効いている** — median と境界の live probe の最大乖離は depeg#701 で DAI **54.9bps**
  （9 境界）、b-harness#801 で **20.6bps**（41 境界）
- **`run.blocks: 504` は 41 epoch にしかならない**（採点窓は `fromBlock..toBlock` = 503 ブロック）。
  42 epoch を厳密に取るなら 505
- **週あたりのガス消費は測れない** — `blocks.csv` は `priorityFeeWei` しか持たず、`gasUsed` も
  実効ガス価格もどこにも記録されていない。得られる唯一の量は **504 ブロックあたり最大 55 tx**
- **G7 の反実仮想も測れない** — 境界の live マーク値を保存していないので「median にしなかったら
  スコアがどう違ったか」が出せない
- 境界ブロックでは equity curve（`events.jsonl` の observation）も median 値になっている。
  曲線は live・median は epoch 系列だけ、が筋
