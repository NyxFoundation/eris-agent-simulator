# ADR 0019: 競技の採点メトリクス（連続経済のリスク調整済み対数成長）

## Status

Proposed（2026-08-12。決定は issue #56 で確定、実装は未着手）

**2026-08-13 改訂** — レビューで issue #56 の記録から 2 点変えた: G7 を「最終境界のみ」から
**全 epoch 境界**へ（§1 / §5。中間境界の mark 操作は std を**下げ**られるので、最終境界だけでは
穴が残る）、§6 の funding に `GAS_BUFFER_WEI` の畳み込みを追加（YAML だけでは 1 ETH にならない）。

## Context

eris は Anvil 上で Arbitrum をフォークする DeFi トレード競争シミュレータで、採点は環境デーモン兼採点者が
run 後に歴史ブロックを読み直して価値系列を再構成する方式（ADR 0006）。評価の枠組みは
**ADR 0017（シナリオベース評価）** が Accepted で、シナリオ =（regime, seed）を並べた行列を回し、
`netPnlUsdc` をシナリオ内で z-score 化してレジーム等重み平均で順位を出す。ただし ADR 0017 §4 自身が
**「メトリクスと式は provisional」**と明記しており、順位は matrix.json から再計算できる派生物として設計されている。

一方、本番競技の構造は ADR 0017 とは違うことが確定している（2026-08-11）: **連続経済 1 本 + 非公開スケジュールの
イベント注入**で、実チェーン・数百人・1 週間。ADR 0017 の実行モデル（`evm_snapshot` / `evm_revert` で
使い捨て世界を仕切る）には実チェーンの対応物が無い（#33 / #35 / #36）。

設計側にはメトリクスのカタログ（M1–M35）があり、そこから 3 案が短リスト化されている。本 ADR はその選択の
着地点と、コードベース側の制約を記録する。

### 解決したい課題

1. **採点メトリクスが未決** — z-score は provisional。#55（参加者 1 人が −1,113 USDC で場の sd を 20.9 → 181.5 に
   膨らませ、他全員を 8.7 倍圧縮した）は field-relative 正規化そのものの性質で、パラメータ調整では消えない
2. **ベンチマークが未定義** — カタログは "noop/HODL" と併記するが、この環境では別物。競技レジームは
   USDC-only 配布のはずなので noop は何も持たず `W_final = W_init` が恒等的に成立し、実測でも全 run で 0.00 だった。
   これは `E = ln(W_a/W_B)` が `ln(W_final/W_init)` に潰れる = **β は 1 銭も除去されていない**
3. **破産の定義が無い** — 価値のフロアも凍結も無く、Aave の `valueUsdc` は `net = collateral − debt` を
   clamp しないので総価値は**負になり得る**（`ln` は −∞ ではなく NaN）
4. **最終評価が 1 断面の pool 読み** — venue / stable の mark は保有者が動かせるプール読み取りで、
   #27 / PR #61 で spot のレジストリ stable もそこに加わった。さらに #61 は最終採点ブロックを
   環境の teardown 後から**競技最終ブロック**へ移した（より悪いバグを直した副作用として、
   agent がまだ取引しているブロックで mark を取ることになった）
5. **funding が宣言と食い違う** — `config/regimes/*.yaml` は `funding.wethWei: "0"` に
   「USDC-only distribution: nobody starts already exposed」とコメントしているが、`funding.ethWei` が
   未設定なので `sdk/src/config.ts:251-253` の既定 **100 ETH** が入り、さらに `fundWallet` が
   `GAS_BUFFER_WEI = 5 ETH` を無条件に上乗せする（`sdk/src/chain.ts:528,543`）。実測（`depeg#701`）で
   noop の初期価値 336,867 は **105 ETH ≈ 311,867（92.6%）+ 25,000 USDC（7.4%）**。
   `netPnlUsdc` では初期・最終を同じ最終価格で評価するため相殺されて見えなかった
6. **ドキュメントに行き先が無い** — ADR 0017 は Accepted で「シナリオ行列 × z-score が採点」と宣言して
   いる。Status の `2026-08-11 追記` が「§3 / §4 は成績決定の構造としては置き換えられる・連続経済側は
   別 ADR で起草する」と既に断ってはいるが、その別 ADR が無いので、docs を読んだ人（または agent）が
   到達できるのは「今の採点は z-score、置き換え先は未定」までになる

### 検討した選択肢

カタログの M4 / M9 / M27 に対応する 3 案。

| | 採点式 | 構造 | 世界の数 |
|---|---|---|---|
| **A. Gauntlet** | `mean_s(E_s)`, `E_s = ln(Ŵ_a / Ŵ_B)` | 独立シナリオのバッチ | ~105 |
| **B. Living Economy** | `mean_e(x_e) − λ·std_e(x_e)`, λ = 0.25 | 連続経済 1 本 × 日次 epoch | 1 |
| **C. Decathlon** | `Σ_j w_j·rank_j`（event 毎に `E` の中央値 → 順位和） | 7 event × 15 instance | ~105 |

### 各選択肢の評価

| 観点 | A. Gauntlet | B. Living Economy | C. Decathlon |
|------|-------------|-------------------|--------------|
| 実チェーンでの実行基盤（#33） | 105–140 の chain 立ち上げ + venue deploy が必要 | **reset ゼロ**（世界が 1 本） | A と同じ |
| #55（外れ値脆弱性） | 解消（benchmark 相対） | 解消（自分の系列のみ） | 解消（順位化） |
| リスク調整 | 無し（終点のみ見る） | **std 項が内在** | event 中央値 + 順位で部分的 |
| ベンチマークの影響 | 零点の位置だけ（順位不変） | **std 項経由で順位が動く** | 零点だけ |
| poc への実装量 | `standings.ts` + benchmark 定義 | epoch 系列の生産が新規 | A + 順位集計 |
| 本番設計（連続経済）との整合 | 不整合 | **一致** | 不整合 |
| 環境が負の和になったときの見え方 | 参加者の大半が負のスコア | 同じだが λ が下限を作る | 順位なので相対的に無害 |

## Decision

**本番の採点は案 B、すなわち連続経済 1 本の上で 4 時間 epoch の対数リターン系列を作り
`score = mean_e(x_e) − λ·std_e(x_e)`（λ = 0.25、provisional）で順位付けする。ベンチマークは noop（現金）、
`x_e` の基礎は通常の live-mark 価値系列とし、field-relative な z-score は退役する。**

### 1. メトリクスの定義

```
x_e   = ln( Ŵ_e / Ŵ_{e-1} )              e = 1..E,  E = 42（4 時間 × 42 = 1 週間）
Ŵ     = max( V, 0.01 · W_init )           G1 破産フロア
score = mean_e(x_e) − λ · std_e(x_e)      λ = 0.25（provisional）
```

- `V` は通常の live-mark 総価値（`core/src/realtime/reconstruct.ts` の `inventory.valueUsdc`）。
  `alphaValueUsdc` は使わない（§3）
- `std` は母集団標準偏差（分母 E）。epoch 数は全員 `E = 42` に固定する（§8 の欠測扱い）
- ベンチマーク noop の差し引きは **mean 項では共通定数なので順位に効かない**。効くのは std 項だけ
  （案 A / C は平均だけの関数なのでベンチマークは零点の位置しか決めない。これが「ベンチマーク選択は
  B 固有の判断」である理由）

#### mean 項は telescope する

`x_e` が対数リターンなので和が畳み込まれ、

```
mean_e(x_e) = ( ln Ŵ_E − ln Ŵ_0 ) / E
```

つまり **mean 項は案 A を E で割ったものに等しく、A と B の差は λ·std 項だけ**。ここから 2 つが従う
（G4 と G7 の判断根拠）:

- 中間 epoch 境界の mark を動かしても mean は動かない（次の epoch で相殺される）。動くのは std だけ。
  ただし**符号は片方向ではない**。境界 k で `ln Ŵ_k += δ` とすると `x_k += δ` / `x_{k+1} −= δ` なので、
  母集団分散の変化は `ΔVar = (2δ/E)·[ (x_k − x_{k+1}) + δ ]`。**`δ < x_{k+1} − x_k` なら分散は下がり
  score は上がる**（= 悪かった epoch の終わりに mark を持ち上げる平滑化。δ を負にすれば
  「良すぎた epoch の後を削る」も同じ）。したがって **G7 は全境界に要る**（§5 G7 に規模とコスト）
- drawdown とその回復は符号が逆の 2 つの大きな epoch リターンとして std に現れる。よって
  G4（MaxDD 失格）は要らない。ただし上の平滑化が狙うのは**まさにその drawdown の隠蔽**なので、
  G4 の不要は「G7 が全境界を守る」ことに依存している

### 2. ベンチマークは noop（現金）

σ_market ≈ 0.0128 / epoch（年率 60% 相当の ETH。**例示値で本環境の実測ではない**）として:

- **noop** — `x_e` は自分のリターンそのものなので `std_e` は自分のボラティリティ。λ が
  「**自分が**取ったリスク」を測る = B をこの形で選んだ理由そのもの
- **HODL** — 市場中立戦略では `√(σ_a² + σ_m²)` が `σ_m` を σ_a = 0.001 で **3.9e-5** しか超えない。
  つまりこの層では **λ が判別せず、B は平均超過リターン（= 案 A）に潰れる**。β を取る層では λ は
  判別するが、測るのは**ベンチマークからの乖離**なので β ≈ 1 のハギングが最も低リスクになり、
  2× レバの罰は noop 基準の `2λσ_m` から `λσ_m` へ半減する。「幸運なレバレッジ週」が本 ADR の
  既知の弱点である以上（下段）、これも HODL を採らない理由に入る

したがって実際のトレードは「**λ を生かす（noop）**」対「**mean からドリフトを抜く（HODL）**」。
`mean − λ·std` の形のために B を選んだのだから、λ を殺す方が損失は大きい。noop は運用コストも
ゼロ（全ロスターに HODL agent を入れる必要も、再 run も無い）。

代償は市場ドリフトが mean に残ること = 幸運なレバレッジ週が報われる。λ はその一部を値付ける
（β = 1 のポジションは `σ_m` を背負うので `λσ_m ≈ 0.0032`/epoch の罰、対する +10%/週のドリフトは
`0.00227`/epoch）が、部分的な答えであって綺麗な解決ではない。**既知の限界として記録し、隠さない。**

### 3. `x_e` の基礎は通常の価値系列（`alphaValueUsdc` ではない）

2 つの理由。1 つ目は §6 の funding 決定によって初めて成立した。

1. **不労の β は元から消える。** ETH 配布をガス相当まで絞れば、誰も市場ポジションを持った状態で
   始まらない。それ以降の β は**選んだ**もので、B は「自分が選んで走らせたポートフォリオ」の
   リスク調整済み評価なのだから、リターンとそのボラの両方を agent に帰属させるのがメトリクスの仕事
2. **`alphaValueUsdc` の β 除去は部分的で、その部分性が誘因になる。** free inventory は参照価格で
   固定するが protocol ポジションは live mark なので、**ETH spot ロングは β が除かれ、GMX 経由の
   ロングは除かれない**。同じ賭けが instrument によって違う点数になる = 直そうとした歪みより悪い

`alphaValueUsdc` は診断値として残す（run 後に「この agent の PnL は α か β か」に答えるのはこれ）。
採点の基礎ではないだけ。

### 4. λ はハードルレート — これが「無行動が上位に来る」への答え

現金だけを持つ agent の系列は平坦なので `mean_e = 0` **かつ** `std_e = 0`、score は厳密に 0。
これを上回る条件は

```
mean_e / std_e  >  λ
```

= **λ は「何もしないのを上回るために必要な 1 epoch あたりの最低 Sharpe」**。週では `0.25 × √42 ≈ 1.62`。
これは場が正の和かどうかに関係なく発火する（#56 本文 point 5 の「負の和の場では大半が負のスコア」は
案 A / C の話）。

ただし §6 のガス予備（1 ETH）があるため**実際の noop の系列は厳密には平坦でない**。ポートフォリオの
約 2.9% 分（§6 の `GAS_BUFFER_WEI` 畳み込み後。今のコードのままなら 15.2%）の β が残るので
`mean_e` も `std_e` も厳密な 0 ではない。上の等式は近似であり、
ガス予備をゼロにできない構造上の下限（ゼロにすると tx を出せない）。

**G5（最低稼働ゲート）は採用しない。** この環境では Aave へ USDC を供給するだけで「資本を展開した」を
満たせる（ほぼ無リスク・ほぼ無リターン）ので、門は「リスクを取ったか」ではなく「金が動いたか」を
測ることになり、最も安い通過方法は駐車場になる（カタログ自身が 稼働の偽装 と呼んでいる）。挙動は
何も変わらずコンプライアンス面だけ増える。

代わりに **KPI**: **noop がまともな参加者の中位より下に来ること**。来なければ環境較正（flow intensity）で
直す。それが失敗したときだけ G5 を再検討する。なお「noop が中位」自体は誤りではない
（大半が実際に負けているならそう言う順位が正しい）。異常なのは **noop が 1 位**になる場合で、それは
環境に利益機会が無いという環境の欠陥。

### 5. ゲート（G1–G7）

| | 決定 | 実装場所 | 保存済み run への後追い適用 |
|---|---|---|---|
| **G1** 破産フロア | 採用。`Ŵ = max(V, 0.01·W_init)` | 採点の算術 | 可 |
| **G2** 破産凍結 | 採用。ただし**採点上の凍結** | 採点（系列の打ち切り） | 可 |
| **G3** 破産率キャップ | **採用しない** + KPI 監視 | — | — |
| **G4** MaxDD 失格 | 採用しない（std 項が代替。§1） | — | — |
| **G5** 最低稼働 | 採用しない（§4 の KPI が代替） | — | — |
| **G6** レバレッジ上限 | 追加しない（既存で足りる） | 既存 `limits.*` + protocol | — |
| **G7** 評価断面の TWAP | 採用。**全 epoch 境界（43 断面）** | `reconstruct.ts` + アダプタ | **不可** |

**G1** は単に `ln(0)` 回避ではない。Aave の `valueUsdc` が `net = collateral − debt` を clamp しないため
総価値は負になり得て `ln` が NaN になる。フロアを置くと破産が定義可能なイベントになり G2 が乗る。
副産物として 1 epoch の最悪対数リターンが有界になるので `std` も暴れない。

**G2 は chain 上で tx を止めず、採点上で凍結する**（floor に触れた epoch 以降を 0 埋め）。理由 3 つ:

- run 挙動を変えないので、これ以前に作った matrix を無効化しない
- **実チェーンでは参加者が sequencer へ直接投げる**ので RPC 拒否は回避され得る。tx の強制停止は
  sequencer 級の権限を要求する = 移植できない仕組みに採点を依存させることになる
- 保存済みデータに後追い適用できる（ルールを変えて再計算できる）

**G3 は連続経済に写らない。** カタログの G3 は「評価単位の 20% 超が破産したらその単位を捨てる」だが、
案 B は世界が 1 本で捨てる単位が存在しない（epoch は独立した世界ではない）。epoch 単位に読み替えると
「みんなで壊せば無効化できる」ゲームを開く。よって採用せず、破産率は環境較正の KPI として見る。

**G6 は「既に十分ある」ことの記録。** Aave の LTV / LT、Liquity の 110% MCR、GMX に加えて、`limits.*` が
per-round の hard cap を pre-submit で検査している（`agentUsdcUnits` / `gmxSizeUsd` /
`aaveBorrowUsdcUnits` / `openPositions` ほか）。ただしこれらは**1 ラウンドのサイズ**の上限であって
レバレッジの上限ではないので、カタログの主張（実質は protocol の担保率で足りる）は正しい。

**G7 は各 epoch 境界の venue / stable probe を直前 N ブロックで median 取る。最終境界だけでは足りない。**
§1 のとおり中間境界の操作は mean を動かさない代わりに **std を下げられる**（平滑化）。しかも中間境界の
操作は次ブロックで解消できるので在庫を持ち越す最終境界の操作より安く、42 回繰り返せる。規模の目安
（E = 42、`x = −0.05` と `+0.03` と残り 0、δ = 0.02）: std 0.008985 → 0.004856、score −0.002722 →
−0.001690 で **+0.00103 = 典型的な `mean_e` の 2 epoch 分**。先読みも要らない（`x_k` が自分の走行平均より
十分低ければ `E[x_{k+1}] = μ` のもとで期待値が負）。実装コストは同じ probe median を 1 回でなく 43 回
取るだけで、`reconstruct.ts` は既に blockNumber 指定で任意断面を再構成できる。安い代替（最後 N 採点断面の
**総価値**の median）を採らない理由は、終盤の正当な取引まで平滑化するので**同じ規則の安い実装ではなく
別の規則**になるから。base インベントリは環境の `PriceFeed` 由来で参加者が動かせないので対象外
（対象は LST の市場価格・eUSD・LP share の reserve・#27 以降の spot レジストリ stable）。

### 6. funding — 「USDC-only」を実際にそうする

```yaml
run:
  economicGas: true                 # ADR 0011。gas を実コスト化し既定 endowment を 3 ETH に落とす
funding:
  ethWei: "1000000000000000000"     # 1 ETH（3 ETH の既定をさらに明示的に絞る）
  wethWei: "0"
  usdcUnits: "100000000000"         # 100,000 USDC
```

**この YAML だけでは 1 ETH にならない。** `fundWallet` は `setEthBalance(ethWei + wethWei + GAS_BUFFER_WEI)`
で残高を置き、`GAS_BUFFER_WEI = 5 ETH` が**無条件に上乗せ**される（`sdk/src/chain.ts:528,543`）。
よって §6 はコード変更を 1 つ含む: buffer を `funding.ethWei` の内側へ畳む（設定値を実効残高として
扱い、下限だけ検証する）。畳まないと下表のとおり狙いの 5 倍以上の β が残る。

ガス予備の比率は ETH ≈ 2,979 USDC 時に:

| | 実効 ETH | ETH の比率 |
|---|---|---|
| 現状（`ethWei` 未設定 + 25k USDC） | 100 + 5 = 105 | **92.6%**（実測 `depeg#701`） |
| `economicGas: true` の既定（3 ETH + 25k USDC） | 3 + 5 = 8 | 48.8% |
| 上の YAML・buffer 畳み込み前 | 1 + 5 = 6 | 15.2% |
| 上の YAML・buffer 畳み込み後 | 1 | **2.9%** |

これが必須な理由: epoch 系列は live mark なので、ETH が 9 割を占める初期配布では**全員の `std_e` が
ETH のボラに支配され、λ は agent ではなく市場を測る**。`netPnlUsdc` では見えなかった欠陥が、B では
致命的になる。

1 ETH は ADR 0011 の較正値（3 ETH、gas 切れ 0 件）より絞るので**前提条件付き**:

- runtime のガスマネージャの下限検証が効いていること（`economicGas` の起動時 fail-fast は
  `MIN_ECONOMIC_GAS_ETH_WEI = 0.5 ETH`（`core/src/realtime/coordinator.ts:234`）なので 1 ETH は通る。
  buffer を畳む変更はこの下限検証を実効残高に対して効かせることでもある）
- **B ハーネスで週あたりの実 gas 消費を測るまで確定値としない**（120 ブロック run で最多の agent が
  33 tx というのは 1 週間へ外挿できない）
- L2 では 1 ETH は絶対額として過大なので、拘束条件は実チェーンでなく poc / anvil 側の較正

副作用: `limits.agentUsdcUnits` が 5,000 USDC / round のままだと endowment の **5%**（今は 20%）になり、
資本を展開し切るのに 20 ラウンド必要になる。上限を endowment に比例させるか、行動頻度が効く設計として
受け入れるかは「決めていないこと」へ送る。

### 7. ADR 0017 のスコープ縮小

```
ADR 0017（as Accepted）                  ADR 0019（本番）
  regime × seed の使い捨て世界 × 35   →   連続経済 1 本（reset 無し）
  snapshot / revert で仕切る          →   非公開スケジュールでイベント注入
  初期 / 最終断面のみ採点             →   4h × 42 epoch の価値系列
  scenario z → regime 等重み平均      →   mean_e − λ·std_e（field-relative でない）
        ↓                                        ↓
  参加者の練習ハーネスとして継続            本番の順位
```

ADR 0017 のうち **superseded されるのは §4 の集計規則だけ**（シナリオ内 z-score → レジーム等重み平均）。
シナリオ行列 runner・7 レジーム・公開/非公開 seed セット・co-location（軸 1 / §6）・失格規則（§4 のうち
集計規則でない部分）・backtest CLI は**参加者の練習ハーネス**として生き続ける。0017 の Status に既にある
`2026-08-11 追記`（「連続経済側の設計は別 ADR で起草する」）を本 ADR を指すよう更新し、全体を
Superseded にはしない（実装が生きている部分まで死んだように読めるため）。

### 8. epoch 境界と欠測

- **poc の較正ハーネスでは epoch = 12 ブロック**（E = 42 → 週 = 504 ブロック、`blockTimeSec: 2` で
  実時間 ~17 分）。anvil の run にはシミュレート時刻が無い（価格パスも stress 窓も run 長も
  ブロック数で書かれており、`lst.simulatedSecondsPerBlock` は LST vault の利回りだけのローカル設定）ので、
  実時刻 4 時間の代わりにブロック数を直接置く。**run 全体の時計は導入しない**。12 を採る理由は 2 つで、
  G7 の窓に 3〜5 ブロック残ること（4 ブロック/epoch だと窓 = epoch になり窓長を較正できない）と、
  504 ブロックが anvil の歴史保持 ~1,050 ブロックの内側に収まり**現行の run 後再構成がそのまま使える**こと
  （24 ブロック/epoch = 1,008 ブロックだと最古の断面が深度限界に張り付き、断面のオンライン取得への
  作り替えが先に要る）
- **境界は実時刻 4 時間を基準に、各境界を最近接ブロックへ写像する**（本番。上のブロック数は poc 側の
  代替であって、実チェーンの定義は 4 時間のまま）。境界は `e = 0..42` の
  **43 本**（42 epoch のリターンを作るには始点 `Ŵ_0` が要る）。採点は blockNumber 指定の
  Multicall3 なので、写像先が確定していれば決定論的で後追い再計算もできる。固定ブロック数にしない
  理由は、block time が揺れる / 停止すると epoch の経済的な意味（4 時間）がずれるから
- **欠測 epoch**: 破産凍結（G2）は以降を 0 埋め、一時的な欠測（プロセス死・観測失敗）は前値継続
  （= リターン 0）。**分母 E は全員 42 に固定する。** 除外して残りで mean / std を取ると epoch 数が
  減って std が不安定になり、早く落ちた方が有利になり得る。環境側の観測失敗を参加者に帰責しないため、
  一時欠測と破産は区別する

## Consequences

### Positive

- **#55 が superseded される。** 採点が field-relative でなくなるので、吹き飛んだ参加者 1 人が
  他人のスコアを圧縮できない
- **実チェーン化（#33 / #35 / #36）の最大の障害が消える。** 105–140 個の世界の立ち上げ（chain bring-up +
  venue deploy）が不要になり、`evm_snapshot` / `evm_revert` への依存も無くなる
- **λ が無行動に対するハードルレートとして機能する**（`mean_e / std_e > 0.25`）。ゲートを足さずに
  「リスクを取らない」を価格付けできる
- **リスク調整が採点に内在する。** G4 が不要になり、`--score-every 1` 縛り（G4 が equity curve を
  読むために要求していた）も外れる
- **G1 / G2 が採点コードの算術に収まる**ので、ルールを変えて保存済みデータに後追い適用できる
- ADR 0017 の実装資産（行列 runner・7 レジーム・backtest）が練習ハーネスとして再利用される

### Negative

- **市場ドリフトが mean 項に残る**（noop ベンチマークの代償）。幸運なレバレッジ週が報われる
  - → λ が β のリスクを部分的に値付ける。完全でないことを rules text に明記し、ドリフトの大きさ自体は
    イベント較正で抑える
- **epoch 系列の生産が新規実装**（現行の採点は初期 / 最終断面しか使わない）
  - → `reconstruct.ts` は既に blockNumber 指定で任意断面を再構成できるので、断面を 43 個取るだけで済む
- **ガス予備が構造的な β の下限になり、noop の score は厳密には 0 でない**
  - → 92.6% → 2.9% まで下げた（`GAS_BUFFER_WEI` の畳み込み込み。§6）。厳密な 0 は ETH を 0 に
    しない限り不可能で、それでは tx が出せない
- **λ = 0.25 と epoch = 4h に理論的な導出が無い**
  - → provisional として公表し、B ハーネスでの実測後に見直す。matrix と同じく生データから再計算できる形にする
- **`limits.agentUsdcUnits` が endowment の 5% になる**
  - → 「決めていないこと」へ送る。行動頻度が効く設計として受け入れる選択肢もある
- **G7 は後追い適用できない**ので、保存済み run では検証できない
  - → 実装順で先に置く（Notes）

### Risks

- **1 ETH で 1 週間を走り切れるか未実測。** gas 切れは「自滅」ではなく環境の設定ミスとして順位を壊す
  - → **週あたり消費は B ハーネスの run では測れない**。圧縮ハーネスでは行動回数がブロック数で決まり
    （504 ブロック）、実チェーンの 168 時間とは無関係だから（「120 ブロックで 33 tx は外挿できない」
    のと同じ理由が 504 ブロックでも消えない）。代わりに **行動あたりの実測 gas × ルールが許す cadence
    × 168h** で予算を組む。ADR 0011 のガスマネージャ下限検証を前提とし、足りなければ USDC 側を
    上げて比率を保ったまま ETH を増やす。なお L2 では 1 ETH は絶対額として過大なので、これは
    poc 側の下限確認にしかならない（§6）
- **G7 は TWAP 窓 N より長く mark を保ち続ける戦略には効き切らない**（全境界へ広げても同じで、
  窓を延ばすほど正当な取引を巻き込む）
  - → 窓 N を epoch 長に対して十分長く取る。両側 probe（`sqrt(sell × buy)`）が既にコストを課している
    （防止はしないが、片側 quote より高くつく）
- **noop が 1 位になる較正**はメトリクスではなく環境の欠陥
  - → §4 の KPI として毎 run 監視し、flow intensity で直す
- **anvil で測った較正値は実チェーンに転移しない**（#33）。「36 体同居で 4/35 しか noop に勝てない」も
  本番設定（数百人・1 週間・実チェーン）の測定ではない
  - → 本番前に実チェーンで再測定する。本 ADR の数値はすべて anvil 実測または例示値として扱う
- **`cex-drift` / `informed-flow` が run-wide config なので連続経済に乗らない**
  - → ブロック指定の窓（`stress.events`）へ移す。`crash` / `whale` / `lending-incident` / #52 / #27 は
    既にイベントなのでそのまま持ち込める

## 決めていないこと

| 項目 | 決めない理由 | いつ決めるか |
|------|------------|------------|
| λ の最終値 / epoch 長 4h | 理論的導出が無く、B ハーネスの実測が必要。provisional として公表する前提 | 1 週間を 1 回通した後 |
| イベント注入スケジュール | 非公開が要件（分布だけ公表する） | 本番運用設計時（別 issue） |
| `cex-drift` / `informed-flow` のイベント化の具体形 | 実装作業であって判断ではない | B ハーネス実装時 |
| `limits.*` を endowment に比例させるか | 「行動頻度を効かせる設計か」という別の判断 | B ハーネスの実測後 |
| 1 ETH のガス十分性 | 週あたり実消費が未測 | 同上 |
| G7 の TWAP 窓 N | epoch 長との相対で決める（全境界に同じ N を使う。poc では epoch = 12 ブロック） | G7 実装時 |
| 断面のオンライン取得（run 後再構成の置き換え） | 504 ブロックなら現行の再構成で足りる。実チェーン（#33）では history が引けないので必ず要るが、それは移行時の作業 | 実チェーン移行時 / epoch を 24 ブロックへ伸ばすとき |
| 参加者向け rules text | ADR は内部の判断記録であって公表文ではない | 本番募集時 |
| 練習ハーネス（ADR 0017）側の採点をどう揃えるか | 練習の目的は執行の練習であって順位の予習ではない | 本番の採点が動いた後 |

### 実装順（run 挙動を変えるものを先に）

後追い適用できない項目を先に置く。順序を逆にすると、検証に使った matrix が次の変更で無効になる。

1. **funding の変更**（`ethWei: 1 ETH` / `usdcUnits: 100k` / `economicGas: true` + `GAS_BUFFER_WEI` を
   `funding.ethWei` へ畳む。§6）— run 挙動が変わる
2. **G7 TWAP**（`reconstruct.ts` + アダプタ。**全境界**）— 後追い適用できないので、これ以前の run では
   検証できない
3. **epoch 系列の生産**（実時刻 4h → 最近接ブロック写像、43 断面 = 境界 0..42）
4. **G1 フロア → G2 採点上の凍結 → score** の実装。本番スコアラは新規に置き、`matrix.json` と同じく
   生の epoch 系列から後追い再計算できる形にする。`core/src/backtest/standings.ts` の z-score は
   練習ハーネスの採点なので**ここでは退役させない**（揃えるかは「決めていないこと」）
5. **`cex-drift` / `informed-flow` のイベント化**
6. `matrix.json` の `AgentScore` に `initialValueUsdc` / `finalValueUsdc` を追加（練習ハーネスの衛生。
   8/9 の sweep の 30 run のうち 5 つは既に runDir が消えており、生スコアが復元できない）
7. **#55 を superseded として close**
