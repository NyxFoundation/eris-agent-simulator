# ADR 0029: 観測から読める fair の向きを残さない

## Status

Accepted（2026-10-28）。公式 12 レジームの config だけの変更で、state dump の焼き直しは要らない。
練習期間（`config/practice.yaml`）は連続経済なので同じ手が使えず、別の変更で扱う（下の「練習期間」）。

## Context

参加者の P を決める値動きのうち、**既に観測したものから先の向きが読める部分**は、腕ではなく
レバレッジの大きさで勝負が決まる。GMX は建てるときに 20 倍まで受け、手数料は片側 0.04〜0.06%、
Aave の借入は EVM 時間で 12 分ぶん（~0）なので、手数料を超える予測可能な向きがあれば、その大きさを
決めるのは在庫ではなく建てられる上限になる（`deployer/vendor/gmx-localhost.patch` の
「any predictable drift in the fair price became a free 100x bet」は手数料と impact を入れる前の話で、
入れた後も向き自体は残っていた）。

fair は OU（`sdk/src/rng.ts` `nextFairPrice`）で、**エポック開始時の fair へ回帰する**。開始時の fair は
state dump の Uniswap 価格 = 毎エポック同じ $3,000 / $60,000 で、agent はブロック 0 に PriceFeed から読める。
κ = 0.02/ブロック（半減期 ~35 ブロック）、ショックは ±0.4% の一様（sd 0.23%）、定常 sd ~1.15%。
「開始時の水準へ向かって建てる」だけで手数料を払った後の期待値が正になる。

`scripts/measurePredictability.ts` は coordinator のブロックループと同じ関数で fair を歩かせ、観測した
ブロックの 2 ブロック後に約定（送信 → 翌ブロック着弾 → GMX keeper が次のブロックで執行）・往復 10bps で
単純な規則の期待値を測る。変更前（2,000 seed / レジーム、名目に対する bps / エポック）:

| 規則 | calm 系 8 本 | cex-drift |
|---|---|---|
| 開始水準へ向かって建てる（1% 離れたら入り、戻ったら出る） | **+454〜+475** | +24 |

名目 $500k（20 倍の上限の内側）なら calm 系で **+$23k / エポック**、負ける確率 ~1%。calm の実測で
venue-arb の noop 比が −242、multi-arb が +23 なので、場の正直な差より 2 桁大きい。T は場の中での偏差
なので、これをやった 1 体が毎エポックの上限 50 + 10√(n − 1) 近くに張り付く。

## Decision

**公式 12 レジームの fair は、エポックの中では martingale にする**（`market.kappa: 0` を 12 本に明示）。

- κ を下げるだけでは足りない。回帰の期待値はおおよそ κ × 保有ブロック × 乖離で、κ が小さいほど乖離が
  大きくなる。往復手数料を下回るには κ ≲ 6e-5（360 ブロックで実質 0）が要る
- ブロックごとのショックは既定のまま（`volatility: 0.004`）。回帰項は 1 ブロックで κ × 乖離 ≈ 0.02% と
  ショックの 1/10 なので、venue 間の乖離（calm 40bps、issue #79）を作るものはほぼ変わらない
- sdk の既定 κ = 0.02 は残す。公式外の config（`config/example.yaml`、venue 単体検証の regime、練習期間）は
  それで動いている。公式 12 本は既定に頼らず明示し、`test/officialMartingale.test.ts` がレジーム × base で
  κ = 0 を検査する（変更前、12 本中 9 本は `market` 節を持たず既定を継いでいた）
- **cex-drift の `kappaMultRange` / `repriceAnchorProb` は外した**。どちらも回帰の強さと戻る先を変える
  ノブで、κ = 0 では何もしない（残すと「1/3 の窓だけ戻らない」レジームに読める）。κ = 0 では全部の窓が
  到達した水準を残す。機構（`core/src/realtime/events.ts`）は公式外の config のために残る

## Consequences

- 変更後（同じ測定）: 開始水準へ向かう規則は calm 系で **−20〜−44bps**（手数料と同じ大きさ = 向きが無い）、
  cex-drift は −443（ドリフトに逆らう）
- **エポック終了時の fair の散らばりが増える**: sd ~1.15% → ~4.4%（0.23% × √360）。全員が同じく持つ部分
  （配布バスケット）は T の μ で消え、保有を大きく変えた agent だけ P の振れが増える（全額 USDC で
  バスケット比 ±$2.1k / エポック。期待値は 0）
- noop の `netPnlUsdc` は以前より大きく 0 から離れる（β が回帰で戻されなくなるので）
- crash / spike / lending-incident / cdp-incident の台形（ramp → hold → decay）は overlay で、この変更とは
  別に読める向きを持つ（ギャップの後に必ず 40% 以上戻る）。測定ではこの 4 本の値は変わらない。別の変更で扱う
- 練習期間は対象外のまま（下）
- 過去の matrix とは比較できない（realization の分布が変わる）

## 練習期間

連続経済では κ = 0 を入れられない。ブロックごとのショックが同じなら 1 日（43,200 ブロック）で sd ~48%、
期間 6 週間で数倍になる。有界に保つには回帰が要り、回帰は読める向きになる（1 日あたりの「期待値 / ノイズ」は
定常乖離 1 sd で √(κh/2)。これを 0.1 に抑える κ ≈ 5e-7 では定常 sd が 200% を超える）。ショックを小さくすれば
両立するが、venue の乖離が減り公式と別の世界になる。どちらを取るかは練習期間の変更で決める。

## Amendment 1: ギャップは戻らない（2026-10-28）

crash / spike / lending-incident / cdp-incident の価格ギャップは overlay の台形（ramp → hold → decay）で、
`recoverFrac: [0.4, 1.0]` が decay で 40〜100% を戻していた。ギャップを見た後に逆張りすれば、OU とは関係なく
最低でも 40% の戻りが取れる（`recoverFrac` を入れた 2026-09-27 の意図は「急変に逆張りして窓で手仕舞う」の
構造的正解を消すことだったが、下限が 0 より上なので利幅を縮めただけだった）。同じ測定で（本文の κ = 0 の後）:

| 規則 | lending / cdp-incident | crash | spike |
|---|---|---|---|
| ギャップが止まったら逆張りして 30 ブロック持つ | +1,128〜1,137 | +2,222 | +1,829 |
| ギャップを見たブロックで追随し 3 ブロック持つ | +158〜165 | +545 | +360 |

戻りの幅を 0 を跨ぐように広げても足りない。decay は直線なので、1 段目を見れば向きと傾きが分かり、残りを
追随で取れる。**観測した後に予測できる続きが無い形**にする:

- **`recoverFrac: [0, 0]`**: ギャップは水準の移動で、ramp の後はエポックの最後まで残る。hold / decay の
  ブロック数は liquidityPull が揃える窓の形として残る（価格には効かない）
- **`rampBlocks: [2, 3]`**（旧 [2, 4]）: 1 段目を見てから出した注文は 2 ブロック後に約定するので、
  4 ブロックの ramp は最後の 1/4 を追随で取れた。遅れている AMM の価格を 1 段目で取るのは従来どおり
  このレジームの裁定
- **全体の偏りを 0 に**: 戻らないと、下に固定の lending-incident / cdp-incident（12〜16%、各 1 本）の分だけ
  「バスケットより base を持たない」が得になる（12 本一様で ~2.3% / エポック。戻っていた頃は残差 30% で ~0.7%）。
  crash は `flipProb: 0.5`（1〜2 本、窓ごとに独立なので 2 本目の向きは 1 本目から読めない）、spike は
  1 本・反転なし・24〜32%（期待 0.28 = lending + cdp の 2 × 0.14）。4 本とも `windowFrac: [0.3, 0.7]`
  に揃える（ずれていると「まだギャップが来ていない」ことが向きを含む）

変更後（4,000 seed / レジーム）: 逆張り・追随はどのレジームでも **−8〜−21bps**（手数料以下）、12 本一様の
「USDC で持つ」は **−6 ± 6bps**（変更前は +68）。

帰結: crash 系のエポックの P はギャップの時点で何を持っていたかで大きく振れる（期待値 0）。victim は戻らない
ので窓の後も清算できる。spike は crash の鏡像ではなくなった（大きさ・本数が違う）。レジームの中身で区別できる
のはギャップが起きた後で、それはこの変更の対象外（起きたことは誰にでも見える）。

## Amendment 2: victim は全レジームに建てる（2026-10-28）

lending-incident と cdp-incident だけが victim を持っていた（Aave 2 体 HF 1.10、Liquity 2 本 ICR 1.20）。
victim のアドレスは env（`ERIS_LIQUIDATION_VICTIMS` / `ERIS_LIQUITY_VICTIMS`）で渡り、env を消しても
開始前の setup で建つのでチェーン上で見える。2 本とも暴落は 1 本・下向き固定なので、**ブロック 0 で
「この先 12〜16% 落ちる」が分かった**。60 エポック中の期待 10 本で、base を手放すか GMX で売り建てれば
レバレッジの分だけ勝てる（`core/src/realtime/agentEnv.ts` は既知の例外として列挙し、「デコイはレジームの
意味を変えるので別に決める」としていた）。

**両 cohort を同じパラメータで公式 12 本すべてに建てる**。env も全レジームで渡る。

- 割れるのはレジームの仕事（κ = 0、本文と Amendment 1 の後、4,000 seed）: lending-incident ~98%
  （暴落前に上がっていると割れない 2% が残る）、crash ~52%（下向きのギャップがあれば）、spike 0.3〜0.6%、
  その他の乱歩だけのレジームで Aave ~3% / Liquity ~5%。デコイが割れるのは普通の清算の仕事
- coordinator の `stress_calibration_warning`「victim がいるのに crash が無い」は、反転しない crash を
  持つレジームでだけ出す（それ以外では crash が無いのが予定どおり）
- Liquity の victim はソートの末尾なので、償還はまず victim に当たる。eUSD のデペグは cdp-incident にしか
  無いので、他のレジームでは償還自体がほぼ起きない
- `test/regimeStartInvariance.test.ts`: env キーは例外なしで 12 本同一、cohort の本数・HF / ICR・サイズも
  12 本同一。`REGIME_REVEALING_AGENT_ENV` は `AGENT_ENV_VICTIMS` に改名（もう例外ではない）

帰結: lending-incident と crash の違いは、ギャップの大きさ・本数・向き（下固定か半々か）だけになる。
どちらも起きた後にしか分からない。

## Amendment 3: 練習期間も同じ形にする（2026-10-28）

本文の「練習期間」が先送りしたもの。練習期間（`config/practice.yaml`）は sdk 既定の OU（κ = 0.02、開始時の fair へ回帰）
で、ギャップは毎日 15〜22% が 3 + 6 + 8 ブロックで全部戻っていた。公式と同じ 2 つの穴で、練習の順位は非公式でも
それで決まりうるし、参加者が練習で調整した戦略が本番の世界と違うものを学ぶ。

1 本のチェーンが 1 か月続くので、公式の手（κ = 0 と、戻らない 15〜32% のギャップ）はそのまま入らない。ブロックごとの
ショックが公式と同じなら乱歩だけで 1 日 sd ~48%、戻らないギャップ 2 本 / 日は上下半々でも 1 か月で ±150%。
有界に保つために回帰を残せば、それが読める向きになる（本文）。よって**揺れを下げて martingale にする**:

- `market: { volatility: 0.00037, kappa: 0 }`。ブロック sd は公式の 1/11（0.021%）で、練習の 1 日の散らばり
  （~4.4%）が公式 1 エポックと同じ。参照価格の揺れが作る venue の乖離は公式より少ない（エピソードとフローは同じ）
- ギャップは公式と同じ形（戻らない・ramp ≤ 3・`flipProb: 0.5` で上下半々）で、大きさは 2〜4%。cexDrift は
  公式の半分の速さ（0.05〜0.1% / ブロック）で、水準は戻らない。`core/src/practiceEpisodes.ts` の `dayTemplates`
- 合計の散らばりは 1 日 ~6.6%（エピソードだけで ~5.1%）、残り 32 日で ~37%（`EventSchedule` で 400 seed）

**期間を止めずに途中から切り替える**（新しい期間はチェーンを戻すので）。`periodResume.ts` に「revise」を足した:
`market.*` と、まだ再生していないエピソードは再起動で変えてよく、`run.endsAt` と `stress.windowBaseBlocks` は
そのまま。coordinator は schedule を変更前と変更後で作り、head + 300 ブロックより前に始まる窓が両方の先頭に
同じ形で並ぶ（同じブロック・同じ引き）ことを確かめ、違えば拒否する（`revisedScheduleProblems`）。

これには引きが行の順に取られ、後ろの行に依存しない stream が要る。ADR 0027 以後、変化キー（`flipProb` /
`recoverFrac` 等）を 1 つでも使うリストはリスト全体の digest を salt に混ぜるので、未来の行を変えると過去の窓が
全部引き直される。**`stress.saltWithEventList: false`** で seed だけの stream に固定する（練習期間はそれまで変化キーを
持たず、ずっとこの stream だった）。salt が防いでいたのは「同じ seed の別レジームが同じ引きをする」ことで、
秘密の seed を持つ 1 レジームの練習期間には当たらない。公式レジームは設定しない。

`config/practice.yaml` は day 23（10/30 22:03 JST から始まる日。チェーンは止まっていた分だけ遅れている）から
書き換えた: `npm run gen:practice-episodes -- --revise-from-day 23`。day 22 までの 220 窓は、変更前と変更後で
同一に解決されることを 5 seed で確認した。再起動が day 23 の窓に間に合わなければ coordinator が拒否するので、
N を後ろにして作り直す（手順は `infra/devnet/README.md`「Revising a period」）。
