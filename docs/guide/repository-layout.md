# Repository Layout

4 npm workspaces (`sdk` / `core` / `example` / `dashboard`) plus a bundled deployer. The only
dependency direction among the first three is `example → sdk ← core`, enforced by
`npm run check:boundaries` (ADR 0015); `dashboard` reads run artifacts off disk and depends on
neither.

```
sdk/src/            contract layer (@eris/sdk)
  action.ts           action validation + ACTION_TYPES_BY_PROTOCOL (the vocabulary a run offers)
  actionSchema.ts     zod schema for agent actions (structural validation, incl. LLM-generated output)
  protocols/          protocol adapters (uniswap / balancer / curve / aave / gmx / lst / liquity
                      + registry / oracles / marketHelpers / deploy)
  chain.ts            clients, anvil cheatcodes, resetFork (snapshot/revert on local)
  observation.ts      observationFor (the environment's scoring and the agent's observation use the same one)
  markets.ts          the market registry (bases, token kinds, decimals)
  stables.ts          market-priced stables — the two-sided executable probe (issue #27)
  valuation.ts        how a holding becomes USDC
  runConfig.ts        YAML config schema (nested lowercase → internal keys)
  constants*.ts       venue addresses (fork: constants.ts / local: constants.local.ts = generated by gen:local-constants)
core/src/           environment daemon + scoring (participants do not touch this)
  cli/                CLI entries (anvil / sim-realtime / backtest / metrics / checkOrdering)
  realtime/           coordinator / priceFeed / events(stress) / liquidity(+Venues) / stableDepeg /
                      whale / lst / liquity / vulnEvents / noArb / reconstruct / marketSeries /
                      agentProcess / flowProcess
  scoring/            epochScore.ts (ADR 0019's mean − λ·std) / metrics.ts (every candidate metric) /
                      aggregate.ts (cross-scenario aggregators, ADR 0020 §5)
  flow/               orderflow bot (logic.ts = pure functions / market-maker.ts = independent process)
  backtest/           backtest shared helpers (state dump manifest / fingerprint / regime resolution;
                      ADR 0016) + standings.ts (scenario-matrix ranking)
  postRunCheck.ts     post-run rule checks (fee limit overruns → violations)
example/agents/     participant template (1 agent = 1 directory is the unit of copy and submission)
  runtime/            generic driver scripts (bot / read / send / llm / improve / deploy / agentLog; reserved names)
  lib/                shared strategy helpers (markets.ts, etc.; reserved name)
  <id>/               the agent itself (agent.ts's decide/run, plus prompt.md to self-improve)
dashboard/          web UI workspace (Vite + React; issue #63) — renders runs/<id>/, live or finished
contracts/          PriceFeed + mock oracles + FlashArb (Foundry)
deployer/           bundled deploy orchestrator (self-contained subpackage that deploys every venue to an empty anvil)
infra/blockscout/   local Blockscout explorer for the sim anvil (issue #31)
config/             YAML config (example.yaml = template / lst.yaml / liquity.yaml / vuln-test.yaml /
                    regimes/ = official regimes / scenarios/ = regime × seed sets; ADR 0016, ADR 0017)
backtest/state/     state dump + manifest (gen:state-dump output; gitignored)
docs/guide/         usage guides (this directory)
docs/adr/           architecture decision records (ADR 0001–0020)
scripts/            gen:local-constants / gen:state-dump / genMetricRegimes / check:strategy /
                    check:boundaries / bundle:agent
test/               unit tests (node --test)
runs/               run output (summary.json / events.jsonl / blocks.csv / market.json / agents/<id>.jsonl,
                    plus matrix-<id>/ for scenario matrices)
```
